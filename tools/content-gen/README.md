# Генераторы черновиков контента

Скрипты, из которых собраны черновики в `docs/content/` и данные окна «Древо рецептов». Черновики правятся здесь, в исходниках, а не в собранных файлах: иначе следующая сборка затрёт правку.

## Рецепты, ресурсы, дроп

Папка `recipes/`, нужен Node.

- `common.js` — ремёсла, ярусы, параметры добычи. Числа — демонстрация, шансы в базисных пунктах.
- `basics.js` — общий пул из 36 базовых: падают во всех биомах с первого (ADR-0023).
- `data1.js`, `data2.js`, `data3.js` — циклы I–II, III–IV, V–VI:
  - биомы: шесть ключей на биом, уникальные;
  - крафтовые биомы и их Забытые боссы;
  - заготовки и изделия — рецепт записан в самом предмете;
  - герои из скрытых рецептов;
  - награды мастерской.
- `build.js` — сборка предметов и рецептов. Героев из крафта берёт из `docs/content/герои/состав-героев.csv`, только читает. Id, имя и источник «крафт» сверяет; расхождение печатает предупреждением.
- `emit.js` — проверки и вывод `design/ui/recipes.js`:
  - достижимость до неподвижной точки;
  - правило §9.2 — не больше двух ресурсов одного ремесла;
  - шесть ячеек и до 100 в ячейке;
  - билет призыва;
  - руины цепочкой: активация руины требует добычи только тех руин, что открываются раньше, — одного активного слота цикла I хватает;
  - ни одного тупика;
  - цена героев с высоким максимумом доблести.

  Там же — полная цена рецептов и счёт развилок.
- `tables.js` — таблицы для документа в `tables.md`.
- `doc-a.md` … `doc-d.md` — текст документа. Таблицы вставляются вместо `@@имя@@`, числа — вместо `{{имя}}`. В `doc-b.md` — летопись Этриона.
- `assemble.js` — склейка текста и таблиц в `docs/content/ресурсы-рецепты-дроп.md`.

Сборка:

```bash
cd tools/content-gen/recipes && node build.js && node assemble.js
```

## Лутбоксы

Папка `lootboxes/`, нужен Node. Черновик `docs/content/лутбоксы.md` — сундуки всех режимов (§23, ADR-0023, п. 7).

- `build.js` — данные сундуков в начале файла: окна редкостей, линии пула, сундуки, выплаты режимов, допущения. Дальше — сборка, проверки и вывод:
  - `design/ui/lootboxes.js` — данные и алгоритм открытия для UI-кита, руками не править;
  - `tables.md` — таблицы для документа;
  - `docs/content/лутбоксы.md` — текст `doc.md`, таблицы вместо `@@имя@@`, числа вместо `{{имя}}`.
- `open.js` — открытие сундука: три броска генератора на предмет, генератор — как в ядре боя. Сборщик вставляет его в `lootboxes.js` как есть.
- `xlsx.js` — чтение листа xlsx без библиотек: талисманы и их веса из `source-data/`.
- Только читает: `design/ui/recipes.js`, `docs/content/герои/состав-героев.csv`, `source-data/Enerium_Талисманы_Финал.xlsx`, `design/ui/talismans.js` — имена, описания, виды и пометка «для команды» талисманов после переработки, `docs/lore/дайджест.md` — раздел «Нельзя показывать раннему игроку», `design/ui/battle.js` — для сверки генератора.
- `check_ui.js` — автопроверка раздела «Лутбоксы» в UI-ките без браузера: CRLF и синтаксис `index.html`, выполнение скриптов прототипа в песочнице, отрисовка раздела на всех сундуках, редкостях, окнах, циклах и неделях; без флажка «для команды» — ни одного спойлерного имени.
- Проверки — любая ошибка, и файлы не пишутся:
  - окна дают 10 000 б. п., ни в одной выплате нет редкости без записей;
  - каждый предмет пула есть в источнике и падает, а не создаётся рецептом; душ, Энериума и рун нет;
  - каждый герой Эхо и каждая редкость талисманов, рабочих и снаряжения выпадают хоть из одного сундука;
  - ×1,7 по планкам, разброс и удержание Эхо (§17.6);
  - лучшее место даёт не меньше худшего;
  - открытие на сиде сходится с точным расчётом, генератор совпадает с `battle.js`;
  - номер, редкость и вес талисмана — как в таблице автора и в `talismans.js`;
  - спойлеры в именах и описаниях талисманов — по словам раздела дайджеста. Спойлеры таблицы автора и решение по ним — таблица документа; итоговое имя или описание со спойлером без пометки «для команды» в `talismans.js` — ошибка. Такие талисманы есть в сундуках только с цикла VI.

Сначала — талисманы: лутбоксы берут из них имена.

```bash
node tools/content-gen/talismans/build.js
cd tools/content-gen/lootboxes && node build.js && node check_ui.js
```

Перезапускать после правки `recipes.js` или состава героев: пулы и отряды Эхо берутся оттуда.

## Герои

Исходник — markdown `docs/content/герои/цикл-N.md`. Оба скрипта читают его и ничего в нём не меняют. Нужен Python 3.
- `heroes/build_heroes.py` собирает `docs/content/герои/герои.csv`, проверяет сеты — 5 героев и бюджет доблести 15 — и печатает распределения по классам, стихиям и расам.
- `heroes/export_ui.py` выгружает героев и сеты в `design/ui/heroes.js` для раздела «Герои» в UI-ките. В выгрузке: витрина, роль, обрывки, главы, бонусы сетов, мотивы дедукции и заметки команды.

```bash
python tools/content-gen/heroes/build_heroes.py
python tools/content-gen/heroes/export_ui.py
```

После правки циклов запускайте оба скрипта.

### Состав героев

`heroes/export_roster.py` выгружает состав игры в `design/ui/roster.js` — для «Героев → Коллекции», «Призыва» и раздела «Состав героев» в UI-ките. Файлы только читает:
- `docs/content/герои/состав-героев.csv` — столбцы по имени, лишние не мешают. «Неприязнь» героя Эхо берётся из одноимённого столбца, иначе — раса его недели;
- тексты глав `docs/content/герои/главы/цикл-N.md`: `## <id> · <имя>`, затем `### <номер> · <заголовок>` и текст. Нет файла — только заголовки глав из CSV;
- ордены черновиков `docs/content/герои/герои.csv`: герой черновика сохраняет орден, донатный — только свой сет;
- механики и N по ступеням — `docs/content/сет-бонусы.md`;
- бонусы донатных сетов и древние цивилизации недель Эхо — `состав-героев.md`.

Числа — в блоке «ДАННЫЕ» в начале скрипта. `RULES['stub']` — заглушки прототипа, чисел нет в источниках. Скрипт проверяет источники, редкости, места донатных сетов и заголовки глав. Расхождения печатает предупреждениями, неразобранные строки — ошибками.

```bash
python tools/content-gen/heroes/export_roster.py
```

После правки состава, глав или сет-бонусов запускайте его заново.

## Способности

Папка `abilities/`, нужен Python 3.
- `extract.py` выгружает таблицу автора `source-data/Enerium_Способности_элементов.xlsx` в `source.json`. Оригинал не меняется.
- `library.py` собирает библиотеку способностей по ADR-0015: восемь наборов — семь школ и «Без школы» — по восемь видов в трёх ступенях по числу целей, ульты, пассивки и реакции, общий набор фарма. Пишет `library.json` для ядра, черновик `docs/content/библиотека-способностей.md` и `design/ui/abilities.js` — раздел «Библиотека способностей» в UI-ките. Проверяет, что названия не повторяются, каждое из 72 названий таблицы использовано один раз, а контроль, дебафф и бафф у наборов свои.

- `assign.py` распределяет библиотеку по героям из `docs/content/герои/герои.csv` и по врагам Мастерской (ADR-0016). Пишет `kits.json`, черновик `docs/content/распределение-способностей.md` и `design/ui/kits.js` — наборы для ядра боя прототипа. Проверяет, что двух одинаковых наборов нет. Наборы попадают в карточку героя UI-кита через `heroes/export_ui.py` — запускайте его после `assign.py`.
- `check_core.js` — автопроверка библиотеки в ядре боя прототипа, нужен Node. Каждая из 339 способностей срабатывает в подобранном бою без ошибок, числа боя и добычи остаются целыми. Запускайте после `library.py` и `assign.py` и после правок `design/ui/battle.js`.

```bash
python tools/content-gen/abilities/extract.py
python tools/content-gen/abilities/library.py
python tools/content-gen/abilities/assign.py
python tools/content-gen/heroes/export_ui.py
node tools/content-gen/abilities/check_core.js
```

## Экономика

`economy/economy.py` — калькулятор к `docs/content/экономика-золото-дух.md`: цена уровней и кругов героя, доход забега, сроки. Числа — данными в начале файла, только целые. Флаг `--sim` перемеряет бой через Node: `design/ui/battle.js` с наборами способностей из `abilities.js` и `kits.js`, отряд — как в прототипе; вывод вставить в `SIM`. Темп цикла I по ADR-0018 — таблица Т15. Нужен Python 3.

```bash
python tools/content-gen/economy/economy.py
```

```bash
python tools/content-gen/economy/economy.py --sim
```

`economy/echo.py` — калькулятор боя в Эхо к `docs/content/эхо-экономика.md` (ADR-0025). Считает:
- уровень и здоровье врагов по ступеням и циклам, раунды по типу врага;
- души за атаку, вершину лестницы за неделю, рейтинговые очки, планки;
- Многоликого и его биом.

Доход душ и уровни отряда он берёт из `economy.py` и `sets.py` через importlib и их не меняет. Числа — данными в начале файла, только целые.
- `--sim` меряет бой ядром через Node на врагах недели из `design/ui/echo-foes.js`; вывод вставить в `SIM_*`.
- `--js` собирает `design/ui/echo-rules.js` — `window.EN_ECHO_RULES`, руками не править, формат — в шапке файла.
- `--doc` заменяет таблицы Э1–Э15 в черновике выводом скрипта; повторная сборка даёт те же байты.

```bash
python tools/content-gen/economy/echo.py
python tools/content-gen/economy/echo.py --sim
python tools/content-gen/economy/echo.py --js
python tools/content-gen/economy/echo.py --doc
```

## Враги Эхо

Папка `echo/`, нужен Node. Черновик `docs/content/эхо-враги.md` — враги девяти недель, Убер-боссы и отряды недели (ADR-0025, ADR-0024, ADR-0016).

- `weeks/*.js` — данные по неделям, файл на неделю:
  - наборы 14 врагов лестницы и Многоликого из библиотеки; у врага может быть своё имя способности и правило цели;
  - защитники каждой ступени и замысел состава;
  - уникальные способности Убер-босса в формате библиотеки, `need` — примитивы, которых в ядре ещё нет;
  - наборы пятерых героев Эхо по доблести и строка, чем отряд отвечает Уберу.
- `build.js` — проверки и вывод. В начале файла — правила: ранги, составы защитников по лестнице, лица Многоликого, список «нужно ядру» (`NEED`). Проверки — любая ошибка, и файлы не пишутся:
  - всё, на что ссылаются наборы, есть в библиотеке или среди уникальных; у рядовых, элит и боссов — только своя школа;
  - число способностей и ульт — по рангу (ADR-0016), у Убер-босса — одна или две ульты (ADR-0025);
  - у каждой ступени четверо защитников своей недели, ранг не выше главного, состав — по лестнице; Многоликий — один;
  - поле уникальной способности, которого нет ни в библиотеке, ни в `NEED`, — ошибка; числа только целые;
  - наборы героев — по доблести от 0 до максимума из CSV, своя школа, последняя — ульта; одинаковых наборов нет, и со 110 героями черновиков тоже.
- `doc.md` — текст черновика, таблицы вместо `@@имя@@`, числа вместо `{{имя}}`.
- Вывод: `design/ui/echo-foes.js` — `window.EN_ECHO_FOES` для ядра и прототипа, руками не править, формат — в шапке файла; `docs/content/эхо-враги.md`.
- Только читает: блок `ECH` в `design/ui/screens/echo.js` — имена, стихии, классы и облик врагов; `abilities/library.json`, `abilities/kits.json`; `docs/content/герои/состав-героев.csv`; `design/ui/roster.js`, `design/ui/recipes.js`.

```bash
node tools/content-gen/echo/build.js
```

Перезапускать после правки библиотеки, состава героев или врагов на экране Эхо.

## Враги биомов 2–4

Папка `biomes/`, нужен Node, для темпа — Python 3. Черновик `docs/content/биомы-2-4.md` — враги, колоды, стражи и темп биомов «Подземный лес», «Библиотека Улариона» и «Искусственный Стоун-Хейм» (ADR-0010, ADR-0016, ADR-0018).

- `data/b2.js`, `data/b3.js`, `data/b4.js` — данные по биомам: враги по строкам `docs/content/враги-биомов.md` — имя, класс, раса, стихия, облик, запись сказителя, набор из библиотеки со своим именем и правилом цели; колода этажей, свита рунного стража, сила биома (`core`), тексты зала (`ui`), уникальные способности.
- `build.js` — проверки и вывод. В начале файла — правила: состав врага по рангу, образцы характеристик Мастерской, мощь по §6, поля уникальных способностей. Любая ошибка — файлы не пишутся:
  - всё, на что ссылаются наборы, есть в библиотеке или среди уникальных своего биома; у библиотечных — только школа стихии врага;
  - число способностей и ульт — по рангу (ADR-0016); имя приёма не занято в библиотеке и не зовёт другой приём у врагов Мастерской;
  - шесть рядовых, шесть элит, босс и рунный страж; босс — только на последнем этаже; этажей и элит — как в черновике добычи `recipes.js`, ставки духа — там же;
  - имена биома, босса, стража и уникального ресурса сходятся с `recipes.js`;
  - ядро собирает таблицу шансов каждого врага; карточки бестиария — здоровье и мощь ядра на этаже первой встречи.
- Вывод: `design/ui/biome-foes.js` — `window.EN_BIOME_FOES`, руками не править; файл сам регистрирует биомы в ядре (`addLib`, `addFoes`, `addBiome`). И `docs/content/биомы-2-4.md` — текст `doc.md`, таблицы вместо `@@имя@@`.
- Арт: готов тот портрет или арена, что стоит в `tools/art-gen/ui-art.json` и выгружен в `design/ui/assets/art/`; остальное прототип рисует заглушкой.
- `sim.js` — прогон ядром: забег, осада, рунный страж, биом 2 с обучения забег за забегом, цикл II по дням.
- `pace.py` — темп: биом 2 против цели ADR-0018, биомы 3–4 по уровням и по дням цикла II. Уровни отряда цикла II берёт из `economy/economy.py` через importlib и его не меняет. Пишет `pace.json` — его берёт следующая сборка; прогон на других данных она не примет.

```bash
node tools/content-gen/biomes/build.js && python tools/content-gen/biomes/pace.py && node tools/content-gen/biomes/build.js
python tools/content-gen/biomes/pace.py --check   # только вердикт темпа
```

Перезапускать после правки данных биомов, библиотеки, ядра боя или выгрузки арта.

## Странник: Память, артефакты, достижения

Папка `wanderer/`, нужен Node. Данные экрана «Странник» прототипа — `design/ui/wanderer.js` (`window.EN_WANDERER`), руками не править.

- `build.js` читает таблицы автора через `lootboxes/xlsx.js`, оригиналы не меняет:
  - `Enerium_Странник_пассивки_Финал.xlsx` — 146 пассивок Памяти. Вес сверяется с листом «Настройки», штуки и суммы весов — с «Сводкой»;
  - `Enerium_Артефакты_Финал.xlsx` — 18 артефактов. Души на все уровни — по правилу автора «база × номер уровня».
- В начале файла — данные Памяти: места, доли редкостей §2.6, цены §0, бесплатные перебросы, пассивка «+1 забег» (ADR-0014). Список `onlyFree` — пассивки только для бесплатных троек, за Энериум их вес 0 (решение 28.09, ×1,7). В данные он уходит полем `onlyFree` пассивки.
- Правки таблиц под систему — блоки `PAS_FIX` и `ART`: было, стало, почему. Сборщик сверяет «было» с таблицей: если автор поменял строку, сборка падает и показывает её. Все правки уходят в `EN_WANDERER.fixes` — их видно в UI-ките.
- `achievements.js` — черновик достижений §29: виды пассивок, категории, «Персональные», «Возрождённые», «Таинственные» с подсказками, первенства сервера по циклам.
- Проверки — любая ошибка, и файл не пишется:
  - хеши таблиц — с `source-data/provenance.json`;
  - имена и номера не повторяются, все числа целые;
  - уровней артефакта не больше циклов с его цикла;
  - «Печать открытых троп» и пассивка Памяти дают семь забегов;
  - у каждой категории достижений есть сундук в `lootboxes.js` на каждый цикл;
  - сумма одного вида пассивок достижений — не больше порога;
  - подсказка таинственного не выдаёт его имя;
  - нет спойлеров: слова раздела дайджеста «Нельзя показывать раннему игроку» и имена цикла «для команды» из `recipes.js`.
- Только читает: `design/ui/lootboxes.js`, `design/ui/recipes.js`, `docs/lore/дайджест.md`.

```bash
node tools/content-gen/wanderer/build.js
node tools/content-gen/screens/check_wanderer.js
```

Перезапускать после правки таблиц автора, `achievements.js` или строк режима «Достижения» в `lootboxes.js`.

## Духовные талисманы

Папка `talismans/`, нужен Node. Черновик `docs/content/талисманы.md` (§26), данные прототипа — `design/ui/talismans.js` (`window.EN_TALISMANS`), руками не править.

- `build.js` читает таблицу автора `Enerium_Талисманы_Финал.xlsx` через `lootboxes/xlsx.js`, оригинал не меняет. Хеш сверяется с `source-data/provenance.json`.
- В начале файла, раздел «ДАННЫЕ», — переработка под систему: правила §26, эффекты новой модели боя, линейки. У линейки — имя, вид, классы до древней, эффект игроку, откуда значение, запись для ядра боя или недостающий примитив, доля в БМ и что поправлено против таблицы — «было» и «почему».
- Номера, редкости и веса талисманов — как у автора: сундуки `lootboxes.js` говорят о тех же предметах.
- Экономика — сколько талисманов приходит по циклам — считается точно по окнам сундуков `lootboxes.js`.
- Пишет `design/ui/talismans.js` и таблицы документа между метками `<!-- @таблица имя -->` и `<!-- /таблица имя -->`. Текст документа вокруг — ручной.
- Проверки — любая ошибка, и файлы не пишутся:
  - каждая строка таблицы автора попала в линейку, значения целые и не убывают с редкостью;
  - привязка автора «(до Древней)» не потеряна;
  - у линейки есть запись для ядра или описанный примитив, охота, добыча и печати в БМ не входят;
  - номер, редкость и вес каждого талисмана — как в пуле сундуков;
  - спойлеры — по разделу дайджеста «Нельзя показывать раннему игроку»: имя или описание со спойлером без пометки «с цикла VI» — ошибка.
- Предупреждает, если пометка «для команды» у сундуков и у талисманов разошлась: значит, лутбоксы ещё не пересобраны.
- Только читает: `design/ui/recipes.js` — 36 базовых для знаков сборщика, `design/ui/lootboxes.js`, `abilities/library.json` — порог «ниже 25 %», `docs/lore/дайджест.md`.
- Сборщик лутбоксов берёт отсюда имена, описания, виды и пометку «для команды»: после сборки талисманов — пересобрать лутбоксы. Разойдутся — упадёт `check_talismans.js`.

```bash
node tools/content-gen/talismans/build.js            # собрать
node tools/content-gen/talismans/build.js --check    # только проверить, что данные и таблицы свежие
cd tools/content-gen/lootboxes && node build.js      # затем — лутбоксы
node tools/content-gen/screens/check_talismans.js
```

Перезапускать после правки таблицы автора, раздела «ДАННЫЕ» или сундуков в `lootboxes.js`.
