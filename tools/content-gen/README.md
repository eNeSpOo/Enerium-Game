# Сборщики данных игры

Скрипты, из которых собраны данные прототипа `design/ui/*.js`, расчёты и таблицы в `docs/content/` и таблицы Excel в `source-data/`. Данные правятся здесь, в исходниках, а не в собранных файлах: иначе следующая сборка затрёт правку.

## Рецепты, ресурсы, дроп

Папка `recipes/`, нужны Node и Python. Редакция 30.09.2026 — поручение автора о крафте; решения — «Решено исполнителем» в документе.

- `common.js` — ремёсла, ярусы (`TIERS`) и семейства (`FAMS`), параметры добычи, лестница Энериума (`ENER`), руническая пыль (`DUST`), крафтовые места и призывы (`CRAFT`), модель стока (`SINK`). Числа — демонстрация, шансы в базисных пунктах.
- `basics.js` — общий пул из 36 базовых: падают во всех биомах с первого (ADR-0023).
- `global.js` — общее для всех циклов: Энериум и рунный ключ в ячейке, кристалл и друза, руническая пыль, строки рун.
- `c1.js` … `c6.js` — по циклу на файл:
  - биомы: шесть ключей, уникальный, эхо босса биома — перекрафт, призыв, трофей;
  - крафтовые места — руины и город: активация, ресурсы, две находки, босс, пробуждение, трофеи;
  - заготовки, изделия, карсты, топливо, приманки призывов — рецепт записан в самом предмете; развилки — в `recipes`;
  - герои из скрытых рецептов и награды мастерской.

  У каждого предмета — `hint` (подсказка Этриона) и `art` (строка арта иконки).
- `build.js` — сборка предметов и рецептов. Героев из крафта берёт из `docs/content/герои/состав-героев.csv`, только читает.
- `emit.js` — проверки и вывод `design/ui/recipes.js`:
  - достижимость до неподвижной точки;
  - правило §9.2 — не больше двух ресурсов одного ремесла; шесть ячеек и до 100 в ячейке;
  - цикл рецепта не раньше цикла выхода, у рецепта есть вход своего цикла;
  - места цепочкой: первый рецепт активации не просит добычи своего места и мест после него;
  - призывы: Энериум, уникальный, своя находка; пробуждения — призыв, Многоликий, находка;
  - ключи — в установившемся расходе, не меньше двух путей; мёртвых ресурсов нет;
  - рунные ключи — только с боссов биома, у донатного сета ключников, в сундуках с малым шансом и за контракты (слово автора 30.09.2026, ADR-0033): рецептов рунных ключей нет, у крафтовых мест и призванных врагов `runeKeyBp` — ноль;
  - лестница Энериума 100 : 1; только целые числа.
- `sheets.js` — листы иконок по 24 и 16, поле `sheet`.
- `sink.js` — модель стока: доход обычного за день (`contracts/capacity.json`, `design/ui/rituals.js`) против расхода мастерской; веса видов ресурса мест (`resWBp`); рунные ключи от крафта напрямую — теперь ноль (ADR-0033).
- `tables.js` — таблицы документов в `tables.md`.
- `tempo.py` — темп руны доблести у обычного (`economy/economy.py`, `valor_pace`) с тем, что сундуки дают сверх модели, в ключах-эквивалентах:
  - рунные ключи: малый шанс в сундуке странника — пропуск, лист даров, достижения — и в сундуках КрафБоссов;
  - руны пределов, осколки и руны доблести сундуков КрафБоссов (ADR-0047) — по цене замены у рунных стражей: сколько ключей стоит добыть столько же боем, руны старших пределов — по курсу перековки.

  Порог — сколько ключей в день не сдвигает руну доблести; ищется с нуля, от сундуков не зависит. Порог цикла — порог × цикл / 3 (`REF`): у старших циклов стражи дороже. Ожидаемое сундуков — `design/ui/lootboxes.js` (`summon.day`, `ev`), сундуки пропуска и листа — `design/ui/pass.js`, число достижений — `design/ui/wanderer.js`. Таблицы в `tempo.md`; `--check` — ошибка, если сумма хоть в одном цикле не ниже порога или крафт даёт рунные ключи напрямую.
- `check_recipes.js` — проверка данных поручения по `recipes.js`: мёртвые, ключи, подсказки, арт, листы, лестница, Энериум и уникальный в призывах, тексты игрока.
- `doc-1.md` … `doc-5.md` — текст `docs/content/ресурсы-рецепты-дроп.md`, в `doc-4.md` — летопись Этриона; `doc-items.md` — `docs/content/ресурсы-каталог.md`; `doc-recipes.md` — `docs/content/рецепты-каталог.md`. Таблицы вставляются вместо `@@имя@@`, числа — вместо `{{имя}}`.
- `assemble.js` — склейка трёх документов.

Сборка:

```bash
node tools/content-gen/recipes/build.js
python tools/content-gen/recipes/tempo.py --check
node tools/content-gen/recipes/assemble.js
node tools/content-gen/recipes/check_recipes.js
```

## Лутбоксы

Папка `lootboxes/`, нужен Node. Черновик `docs/content/лутбоксы.md` — сундуки всех режимов (§23, ADR-0023, п. 7).

- `build.js` — данные сундуков в начале файла: окна редкостей, линии пула (`LINES`), сундуки (`BOXES`), выплаты режимов, лестница планок (`LADDER`), призванные враги (`SUMMON`), темы и типы сундуков КрафБоссов (`THEMES`, `SUMMON_TYPE`, `STRONG`, `SUMMON_LAW`), допущения. Дальше — сборка, проверки и вывод:
  - `design/ui/lootboxes.js` — данные и алгоритм открытия для UI-кита, руками не править; `summon` — сундук за победу над призванным врагом для экрана Эхо, день обычного — для `recipes/tempo.py` и `equipment/build.js`;
  - `tables.md` — таблицы для документа;
  - `docs/content/лутбоксы.md` — текст `doc.md`, таблицы вместо `@@имя@@`, числа вместо `{{имя}}`.
  - `--check` — те же законы, файлы не пишутся: сверка, что три выхода свежие;
  - `--laws` — печать запаса по законам сундуков КрафБоссов: худший враг, цикл и число у каждого закона.
- **Сундук** в данных: `lines` — случайные линии `[линия, вес, с цикла, по цикл]`; `items` — случайных записей по редкости сундука или `total` — всего записей с гарантированными; `sure` — гарантированные записи: `[линия, сколько, с цикла]` — своей линии на редкости сундука (гарантия сундука осколков — запись вида `target`, осколки герою-цели недели), `[[[линия, вес, с цикла, по цикл], …], сколько, с цикла]` — из своих линий по окну сундука; `week: true` — сундук помнит неделю (расу); `theme` и `type` — тема и тип врага у сундука КрафБосса.
- **Призванные враги** (слово автора 01.10.2026; ADR-0047) — сундук за каждую победу над врагом из предмета крафта, вне лестницы недели. У каждого КрафБосса — свой сундук:
  - **тема — по ремеслу цепочки**, поле `spec` записи `drops.craftBosses` в `recipes.js`: охота — «Добыча» (ресурсы), инженерия — «Казна» (валюта), кузнечество — «Горн» (снаряжение и сильные руны), зачарование — «Рунный ларь» (случай среди рун), алхимия — «Урна имён» (осколки многих героев), портняжное дело — «Общий» (прежний «Сундук призыва»). Состав тем — `THEMES`;
  - **тип врага** (поле `g`) задаёт размер и окно, `SUMMON_TYPE`: босс — 3 записи, окно «лестница», одна запись темы наверняка, сильная линия — 10 % случайных записей; Убер — 3 записи, чистое окно, одна темы и одна сильной линии наверняка; Пробуждённый — 4 записи, чистое окно, две темы и одна сильной линии наверняка, валюта ×2;
  - **редкость** — сила врага + 1 (цикл, у пробуждённого — на цикл выше); поле `workerBoxRarity` сверяется;
  - **сильная линия** — с силы IV (`STRONG`): предмет снаряжения, руна предела IV–V, осколки доблести; у «Горна» — только руны и доблесть, у «Рунного ларя» — только снаряжение;
  - сундук темы и типа — свой id (`forge`, `forge_u`, `forge_a`) и свой источник в `modes`;
  - Лик недели — сундук осколков своей недели, редкость считает закон доли героев недели (ADR-0025).

  Законы 1–10 — раздел «призванные враги» в `build.js`, нарушение — ошибка сборки: 1 — свой сундук у каждого врага, размер и «наверняка» по типу; 2 — дороже призыв — не хуже сундук; 3 — нет запрещённого: рун, доблести, ресурсов мест и находок нет в сундуках режимов, билетов призыва, душ, Энериума, героев целиком и изделий нет нигде; ключи — малым шансом; 4 — руны, доблесть и ключи сундуков в ключах-эквивалентах ниже порога темпа доблести в каждом цикле (`recipes/tempo.md`); 5 — снаряжение — не больше половины потока Арены и Лиги по очкам редкости (сверяет и `equipment/build.js`); 6 — ресурсы «Добычи» — не больше 10 % добычи обычного за день, по каждому виду; 7 — «Казна» — не больше суток дохода на сундук, валюта всех сундуков — не больше 5 % недельного дохода; 8 — «Урна имён»: героев рулетки — не больше прокрутки в неделю, героев Эхо — не больше 10 % недельной гарантии Эхо; 9 — ×1,7 плательщика по числу сундуков каждой темы и по мерам; 10 — шансы видны до призыва, имя врага — после первой победы: его держат проверки экранов (`check_ui.js`, `screens/check_echo.js`). Имена сундуков, линий и источников сверяются с лестницей спойлеров (`lore/ladder.js`). Поток шардов рабочих, талисманов и снаряжения из сундуков КрафБоссов входит в закон стока З9 лестницы планок. День обычного — по модели стока (`recipes.js`, `stats.sink`; доли видов — `recipes/common.js`, `SINK.summonMixBp`), Многоликий — по победам в Эхо (`contracts/capacity.json`) и шансу из `echo-rules.js`. Экран — наградная часть `design/ui/screens/echo.js`, проверка — `screens/check_echo.js`.
- `open.js` — открытие сундука: гарантированные записи первыми — своей линии один бросок, из своих линий по окну три; затем три броска генератора на предмет; генератор — как в ядре боя. Сборщик вставляет его в `lootboxes.js` как есть. Кому идут осколки героя-цели недели, решает не алгоритм, а «сервер» героев Эхо при открытии: цель недели, дальше по цепочке, собран отряд недели — прах Эха.
- `xlsx.js` — чтение листа xlsx без библиотек: талисманы и их веса из `source-data/`.
- Только читает: `design/ui/recipes.js`, `docs/content/герои/состав-героев.csv`, `source-data/оригиналы-2026-09-26/Enerium_Талисманы_Финал.xlsx`, `design/ui/talismans.js` — имена, описания, виды и пометка «для команды» талисманов после переработки, `docs/lore/дайджест.md` — раздел «Нельзя показывать раннему игроку», `design/ui/battle.js` — для сверки генератора; для призванных врагов — `recipes/common.js`, `recipes/tempo.md`, `contracts/capacity.json`, `design/ui/echo-rules.js`; комплект осколков героя — `design/ui/roster.js`, `rules.stub.shards`.
- `check_ui.js` — автопроверка раздела «Лутбоксы» в UI-ките без браузера: CRLF и синтаксис `index.html`, выполнение скриптов прототипа в песочнице, отрисовка раздела на всех сундуках, редкостях, окнах, циклах и неделях — гарантированные записи первыми и с пометкой «наверняка», в карточке — блок «Наверняка»; без флажка «для команды» — ни одного спойлерного имени. У каждого КрафБосса — сундук своей темы и типа; «За победу» до призыва (`EN_ECHO.reward`) называет сундук темы и что в нём наверняка, имени врага не называет. Раздел живёт в `index.html`; новые сундуки и записи он показывает через дополнения в конце `design/ui/screens/chest-open.js`.
- Открытие новых записей на экране — `design/ui/screens/bag.js` (выдача, карточка сундука, лист «Состав и шансы») и `screens/chest-open.js` (окно открытия, вид сундука темы — `coKind`). Законы открытия с мутациями — `screens/check_chest_open.js`: гарантия выдана цели недели и не теряется; повтор номера ничего не выдаёт; сундук темы даёт запись темы наверняка; в сундуке нет запрещённого. Флаг `--mut` печатает, что закон нашёл у каждой поломки, `--laws` — быстрый прогон только законов.
- Проверки — любая ошибка, и файлы не пишутся:
  - окна дают 10 000 б. п., ни в одной выплате нет редкости без записей;
  - каждый предмет пула есть в источнике и падает, а не создаётся рецептом; душ и Энериума нет; руны пределов, осколки и руны доблести — только в сундуках КрафБоссов;
  - каждый герой Эхо и каждая редкость талисманов, рабочих и снаряжения выпадают хоть из одного сундука;
  - ×1,7 по планкам, разброс и удержание Эхо (§17.6);
  - лучшее место даёт не меньше худшего;
  - открытие на сиде сходится с точным расчётом, генератор совпадает с `battle.js`;
  - номер, редкость и вес талисмана — как в таблице автора и в `talismans.js`;
  - спойлеры в именах и описаниях талисманов — по словам раздела дайджеста. Спойлеры таблицы автора и решение по ним — таблица документа; итоговое имя или описание со спойлером без пометки «для команды» в `talismans.js` — ошибка. Такие талисманы есть в сундуках только с цикла VI.

Рунные ключи — главная линия только в сундуке ключей, награде контрактов. В сундуке странника и в сундуках КрафБоссов «Казна» и «Общий» у ключей малый вес — около 3 % случайных записей: так по слову автора 30.09.2026 ключи падают «в различных лут боксах но с мелким шансом» (ADR-0033). Прямые ключи пропуска, листа даров и крафта убраны.

Календарь — лист «Дар дня» из `pass/build.js` (`CAL`, ADR-0030, п. 22в; ADR-0031, п. 20): строки сундуков календаря сборщик собирает из листа, своего календаря у него нет. `pass/build.js --check` сверяет лист с календарём `lootboxes.js`: разошлись — пересобрать лутбоксы.

Сначала — талисманы: лутбоксы берут из них имена.

```bash
node tools/content-gen/talismans/build.js
cd tools/content-gen/lootboxes && node build.js && node check_ui.js
node build.js --check      # только законы и свежесть
```

Перезапускать после правки `recipes.js` или состава героев: пулы, отряды Эхо, призванные враги и комплект осколков берутся оттуда. Ещё — после `recipes/tempo.py` (таблица ключей и темпа доблести в документе), ёмкости `contracts/capacity.py` и `economy/echo.py --js`. Пропуск хранит отпечаток `lootboxes.js` (`lootSha`): после пересборки лутбоксов — `pass/build.js`.

Сундуки КрафБоссов и темп доблести читают друг друга: лутбоксы берут порог из `recipes/tempo.md`, `tempo.py` — день обычного из `lootboxes.js`. Порог от сундуков не зависит, поэтому круг сходится за один проход: лутбоксы → `python tools/content-gen/recipes/tempo.py` → лутбоксы → `node tools/content-gen/equipment/build.js` (источник «сундук КрафБосса» в снаряжении) → `node tools/content-gen/recipes/assemble.js` (таблица темпа в документе рецептов).

Где неделю заканчивают игроки в «Контрактах» — не допущение, а прогон сборщика контрактов: сборка читает `design/ui/contracts.js` и сверяет планку обычного и увлечённого во всех циклах. Разошлось — ошибка сборки: поправить `typical` режима «Контракты». Сборщик контрактов читает `lootboxes.js`, но не `typical` — круга нет.

## Герои

Исходник — markdown `docs/content/герои/цикл-N.md`. Оба скрипта читают его и ничего в нём не меняют. Нужен Python 3.
- `heroes/build_heroes.py` собирает `docs/content/герои/герои.csv`, проверяет сеты — 5 героев и бюджет доблести 15 — и печатает распределения по классам, стихиям и расам.
- `heroes/export_ui.py` выгружает героев и сеты в `design/ui/heroes.js` для раздела «Герои» в UI-ките. В выгрузке: витрина, роль, обрывки, главы, бонусы сетов, мотивы дедукции и заметки команды.

```bash
python tools/content-gen/heroes/build_heroes.py
python tools/content-gen/heroes/export_ui.py
```

После правки циклов запускайте оба скрипта.

### Состав героев

`heroes/export_roster.py` выгружает состав игры в `design/ui/roster.js` — для «Героев → Коллекции», «Призыва» и раздела «Состав героев» в UI-ките. Файлы только читает:
- `docs/content/герои/состав-героев.csv` — столбцы по имени, лишние не мешают. «Неприязнь» героя Эхо берётся из одноимённого столбца, иначе — раса его недели;
- тексты глав `docs/content/герои/главы/цикл-N.md`: `## <id> · <имя>`, затем `### <номер> · <заголовок>` и текст. Нет файла — только заголовки глав из CSV;
- ордены черновиков `docs/content/герои/герои.csv`: герой черновика сохраняет орден, донатный — только свой сет;
- механики и N по ступеням — `docs/content/сет-бонусы.md`;
- бонусы донатных сетов и древние цивилизации недель Эхо — `состав-героев.md`.

Числа — в блоке «ДАННЫЕ» в начале скрипта. `RULES['stub']` — заглушки прототипа, чисел нет в источниках. Правила источника — тоже данные (ADR-0019; ADR-0030, п. 5а): `RULES['maxV']` — личный максимум доблести по источнику и циклу героя, у рулетки II — 2, III–IV — 3, V–VI — 4; `RULES['rarity']` — редкости источника, за золото только обычная и редкая. Скрипт проверяет источники, редкости и максимумы по этим правилам — расхождение с ними ошибка, — каталог золота по редкости после мест обучения, места донатных сетов и заголовки глав. Остальные расхождения печатает предупреждениями, неразобранные строки — ошибками. В `srcInfo` источника — `maxByC`, максимум по циклу героя, и `rar`, героев по редкостям.

Пол героя (`sex`: `m` или `f`) — для портрета Странника: игрок выбирает портрет из своих героев своего пола. Берётся из столбца «пол» состава («м» или «ж»), если он есть; иначе сборщик выводит его из грамматического рода — первое сказуемое каждого предложения «кто он», слово-название в начале («Эльфийка», «Стражница»), «Её» или «Его», и сильнее всего — голос героя в главах: глагол рядом с «я» («я пришла», «давала я»). Правила и списки слов — `SEX` в блоке «ДАННЫЕ». Не вывелся — предупреждение, поле не пишется. Сейчас выведен у всех 360: 204 мужчины, 156 женщин.

## Способности

Папка `abilities/`, нужен Python 3.
- `extract.py` выгружает таблицу автора `source-data/оригиналы-2026-09-26/Enerium_Способности_элементов.xlsx` в `source.json`. Оригинал не меняется; на его прежнем месте — таблица из данных игры (`tables/build.py`).
- `library.py` собирает библиотеку способностей по ADR-0015, ADR-0050 и ADR-0051 — 397 записей: 386 — героям и врагам, 11 — черты врагов:
  - восемь наборов — семь школ и «Без школы» — по восемь видов в трёх ступенях по числу целей, ульты, пассивки и реакции, общий набор фарма: прежние 339 записей не меняются;
  - 37 сочетаний (`COMBOS`) — способность из двух записей: одна строка в таблице шансов, обе части действуют за один ход. Законы Б1–Б5: части — две активки или две ульты; коэффициент части — 60 % своего, контроль, дебафф и бафф — на раунд короче; школа — школа первой части; вторая часть другой стихии — «сочетание двух стихий»; имена не повторяются;
  - 10 черт — пассивки-связки на примитивах ядра `nthBasic`, `hotAura`, `ctrlFirm`, `party`, `dmgReduce` и условии «цель под любым контролем»;
  - 11 черт врагов (`FOE_TRAITS`, набор «Черты врагов», ADR-0051) — 5 пассивок и 6 реакций именных врагов: ответ на связки героев. Примитивы ядра — `shed` (снять с себя дебаффы или урон по времени раз в N ходов), `ccd` с `floor` (ход под контролем копит урон), `debuffed` с `ctrl` и `reflect` (не принять дебафф, вернуть контроль наложившему), `nthBasic` с `then: dispel` (сорвать щит и лечение по времени), прежние `dotReduce`, `lifesteal`, `hit`, `critTaken`, `foeUlt`. Героям не раздаются: `assign.py` и подбор их не видят. Описания — тем же сборщиком и по тем же законам О1–О4; у реакции врага — своё «когда» (`TRIG_TPL_FOE`): «враг» в нём — герой;
  - метки связок у каждой записи (`tags`): что запись кладёт, чем пользуется, когда работает как черта героя с доблести 0 — по ним `assign.py` собирает наборы.

  - **описания** (слово автора 06.10.2026, ADR-0052): текст `d` каждой записи собирается из её данных и объясняет, что способность делает. Название эффекта не стоит голым: способность кладёт эффект — рядом его действие с числами записи («Осыпание на цель, 4 раунда: −30 % физической защиты»), только пользуется им — коротко в скобках («по целям под стужей (замедление)»). Процент удара, лечения и щита — от атаки героя. Слова эффектов — словарь `FXW` и шаблоны `eff` наборов; тексты связок, пассивок, реакций и фарма — шаблоны с полями записи (`+{pct} % урона`); текст сочетания собирается из его частей. У реакции в описании — когда она срабатывает; шанс реакции числом не назван: он свой у героя каждой редкости (`chR` набора), экран показывает его рядом. В готовом тексте число не отрывается от «%» и своего слова — неразрывный пробел.

  Пишет `library.json` для ядра, черновик `docs/content/библиотека-способностей.md` и `design/ui/abilities.js` — раздел «Библиотека способностей» в UI-ките, девятый набор — «Сочетания». Словарь эффектов уходит в оба файла полем `fx`: в `abilities.js` — имя, что это коротко, определение и шаблон объяснения с числами ядра (его берёт окно карты в бою), в `library.json` — ещё основы слов и образец объяснения для проверки текстов. Проверяет, что названия не повторяются, каждое из 72 названий таблицы использовано один раз, а контроль, дебафф и бафф у наборов свои.
  - **Законы описаний О1–О4** — в сборке, нарушение — ошибка, файлы не пишутся: О1 — в описании нет названия эффекта без объяснения; О2 — в шаблонах нет цифр: числа только из данных; О3 — описание не длиннее `DESC_MAX` (200) знаков, без служебных знаков и знаков разметки; О4 — у реакции сказано, когда она срабатывает.
  - `--check` — только сверка: законы держатся, выходы на диске совпадают со сборкой.
  - `--mut` — проверка мутацией: 17 поломок описаний, каждую должен поймать свой закон, и 8 правок баланса — число в данных должно само сменить текст.

- `assign.py` собирает наборы способностей всем героям состава `docs/content/герои/состав-героев.csv` и врагам Мастерской (ADR-0016, ADR-0031, п. 7; ADR-0050 — «каждый герой сборный»). Класс, школа, редкость и личный максимум доблести — из состава.
  - **Черта именного врага** (ADR-0051): элитам, боссу и рунному стражу Мастерской — по черте из набора «Черты врагов», кому какая — `FOE_TRAIT`. Черта стоит в наборе отдельным местом с меткой `trait` — сверх числа способностей по рангу; у рядовых её нет.
  - **Набор героя:** доблесть 0 — пара «активная и черта» (пассивка или реакция, связанная с этой активной или с навыками соседей), каждая следующая доблесть — одна запись, последняя — ульта; способностей — личный максимум + 2. Ульта-сочетание — вторая ульта на предпоследней доблести героя с максимумом 4–5.
  - **Откуда набор:** пятёрка обучения (`TUT`) и примеры принятого проекта (`FIXED`) — по именам способностей; наборы отрядов недели Эхо — из `design/ui/echo-foes.js`; 110 ручных наборов героев черновиков `герои.csv` — основа набора героя состава (не подошёл по классу или школе — не берётся); остальным — автомат. Активные доблести 0 и черты раздаёт подбор наименьшей цены по циклу, выбор детерминирован — сид от id героя.
  - **Законы Н1–Н9** — в `--check`, нарушение — ошибка, файлы не пишутся: пара доблести 0; шаги по доблести; черта связана; неповторимость — набор и пара доблести 0 одни на игру, активная доблести 0 одна на цикл, одна черта — не больше чем у трёх героев цикла; школа — приёмы «Без школы» любому, сочетание двух стихий — только рулетке, Эхо, крафту и донату; с максимумом 4–5 — сочетание, и каждое сочетание библиотеки — хотя бы у одного героя; донатная поддержка без урона; пятёрка обучения и примеры проекта — как записаны; набор героя Эхо — отряда его недели.
  - `--mut` — проверка мутацией: 19 поломок наборов, каждую должен поймать свой закон.

  Пишет `kits.json` (`roster` — наборы героев состава, `heroes` — ручные наборы черновиков как собраны), черновик `docs/content/распределение-способностей.md` и `design/ui/kits.js` — наборы для ядра боя прототипа по id героя состава; id черновика ведёт к тому же набору. После правки состава или отрядов Эхо (`echo/build.js`) — перезапустить, затем перемеры `economy.py --sim`, `sets.py --sim`, `echo.py --sim`: отряд прототипа меряется этими наборами. - `check_core.js` — автопроверка библиотеки и наборов в ядре боя прототипа, нужен Node. Каждая из 386 способностей героев и врагов срабатывает в подобранном бою без ошибок, числа боя и добычи остаются целыми; у сочетания обе части действуют за один ход; имена сочетаний и черт не совпадают с именами врагов.   - **«Боевая мощь»** М1–М5 — формула §6 одна на героев и врагов (`EnBattle.bm`): карта без способностей — слой 0; способность и черта мощь не уменьшают; числа целые; исход боя от чисел мощи не зависит;
  - **«Лестница типов»** Л1–Л5 — порядок типов, раунды и иммунитет к контролю — слова автора 06.10.2026: семь ступеней по порядку `RULES.ladder`, раунды 10–15–20–25–30–35–50, иммунитет 0–0–0–25–50–75–100 %, Арена и Лига — 25 раундов; Многоликий берёт раунды у Пробуждённого, «Забытого» среди типов нет; состав врага по рангу вверх по лестнице не беднее. 14 поломок — каждую ловит свой закон. Неприязнь героев Эхо по циклу и расы врагов Мастерской и Многоликого сверяет `screens/check_echo_battle.js`.

  Запускайте после `library.py` и `assign.py` и после правок `design/ui/battle.js`.

Первая планка — `plank1` в `echo-rules.js`: экраны Эхо и «Неделя» берут пороги оттуда. Плательщик — время обычного, души × худший настоящий день Т12 калькулятора экономики. ## Старт с чистого листа: уровни Странника 1–10 цикла I

Папка `start/`, нужен Node. Сценарий нового игрока за два биома цикла I — уровни Странника, их этапы, награды и окно уровня (§16, §31, ADR-0018, ADR-0019, ADR-0031). Черновик — `docs/content/старт-с-чистого-листа.md`.

- `data.js` — сценарий: опыт за вехи §16, формула дальше 10-го, герои обучения по порядку найма и их фикстура прогонов, руна обучения, открытия (`OPEN`: что, одной-двумя фразами, куда ведёт «Попробовать»), ворота разделов, вкладок и мест отряда (`GATES`), уровни 1–10 (этап, награда, слово проводника), коридоры темпа (`PACE`), политика игрока (`BOT`), обучение по сценарию (`SCRIPT`: какие шаги в первый раз ведут к своей кнопке; сундук уровня 3 с заданным содержимым, витрина и покупка Лавки, первый артефакт — из них сборщик собирает `EN_START.tut`, `world-sim.js`, `tutOf`), ADR-0040. Окно перехода в цикл II — окно «Событие нового цикла»: его содержимое собирает сборщик цикла (`cycle/`, ADR-0041).
- `rules.js` — алгоритм «сервера» уровня, общий для сборщика и прототипа: веха — один раз, уровень — опыт и этап, `claim` — операция с номером, повтор ничего не выдаёт; награда — «Дар Страннику» и сверх него награда сценария; `skip` — пропуск обучения одной операцией с номером: аккаунт — в итог сценария, повтор ничего не выдаёт. Сборщик вставляет его в `design/ui/start.js` как есть.
- `bot.js` — канонический игрок, одна политика на два мира: найм, покупка артефакта активных биомов (шаг `trail`: сразу после первого найма, до первого забега — без него мир отказывает в забеге, ADR-0054), первый рецепт, руна обучения, предел, дух в уровни (самый низкий — первым), страж или забег. Каждое действие — в журнал: из него сборщик собирает шаги обучения.
- `world-sim.js` — мир на ядре боя: забеги и стражи — `battle.js` на `biome-foes.js`, герои — фикстура `biomes/sim.js`, добыча — тем же порядком бросков, что прототип; журнал добычи по забегам и этажам, с `opt.loot` — добыча из таблицы сценария.
- `build.js` — сначала полный путь: лес забег за забегом, как прежде, — мера того, что лес даёт. Погружения Подземного леса (ADR-0049, `data.js`, `DIVES`) — его забеги, где встречается новое: первый забег леса, этап уровня Странника, первая встреча с хозяйкой леса, победа над ней и новые рубежи между ними; однообразные забеги между погружениями заменяет дар погружения — их добыча, сид добычи погружения — забег полного пути. Перед каждым погружением — урок: первый по порядку данных, о котором уже есть что рассказать. Дальше два прохода: первый берёт уровни по этапам и даёт пороги опыта (дары считает по ходу), второй идёт по правилу сервера с дарами из данных и обязан повторить первый. Законы: сценарий проходится; пороги растут; темп — биом 1 7–10 минут боя, биом 2 20–60; погружения — 5–10 заходов с входом к стражу, столько, сколько уроков, каждое глубже прежнего, хозяйка леса — в последнем, окно каждого урока новое, герой урока — по роли, его приёмы — из данных, в текстах уроков ни имён героев, ни приёмов, итог обучения тот же, что у полного пути; найм не ждёт золота; ключей хватает с запасом; руна обучения, рецепт и предел — в цикле I, предел I у всех пятерых к циклу II; рунные стражи без провалов по уровню до 160-го; показатель духа ядра — тот же, что `economy.py`; тексты — без спойлеров и служебного; только целые. Обучение по сценарию (ADR-0040): шаги `script`, добыча `loot`, итог пропуска `skip`, подсказка `hint`; сценарий, сыгранный по шагам, и он же с добычей из таблицы приходят к итогу прогона; пропуск с каждого уровня 1–10 — тот же итог; ресурсы первого рецепта дарит уровень Мастерской, рецепт — следующий шаг. Вывод — `design/ui/start.js` (`EN_START` и `EnStart`, с каноническим путём для проверки прототипа, сценарием, добычей и итогом пропуска), `start/start.json` для калькуляторов (`biomes/pace.py` берёт оттуда биом 2 цикла I, `economy/economy.py` — золото и дух обучения, Т15; там же итог пропуска `skip`), таблицы черновика между метками. `--check` — законы и свежесть, `--print` — таблицы.

- `pool.js` — алгоритм, общий для калькулятора и прототипа: слоты, роллы и карточки по уровням артефактов, пул вкладки на сиде (у рабочих пять бросков на карточку — уникальный, редкость, бригада, биом, имя; у героев три), награда карточки, время с ускорением рабочих, исход старта на сиде карточки, цена пробуждения рабочего; мера ступеней недели — загрузка своих мест (ADR-0047): `weekMs`, `capMs`, `load`, `stepOf`. Сборщик вставляет его в `rituals.js` как есть.
- `build.js` — раздел «ДАННЫЕ»: правила §19 и таблиц автора, сетка по вкладкам, бригады, ставки наград, имена, тексты игрока; допущения прогона и цели долей. Дальше — прогон дней циклов II–VI у обычного, увлечённого, занятого и плательщика тем же пулом на сидах, приток шардов из сундуков `lootboxes.js`, сравнение с доходом забегов из `contracts/capacity.json`. Пишет `design/ui/rituals.js` и таблицы документа между метками `<!-- @таблица имя -->` и `<!-- /таблица имя -->`; текст документа — ручной.
- Проверки — любая ошибка, и файлы не пишутся:
  - генератор совпадает с сундуками (`EnLoot`); всё целое, длительности кратны 10 000 мс; сетка 30 минут — 12 часов, рабочие вдвое короче; бригада 1–5; души — только у героев;
  - шаг и потолок «Караванного шатра» сходятся с `wanderer.js`; у каждого биома шесть ключей и уникальный; общий пул — 36;
  - пул детерминирован, уникальный — только в бесплатном и не больше одного, биом — открытый; исход даёт столько предметов, сколько на карточке;
  - доли ритуалов у обычного — в целях по золоту, духу, душам и базовым; у увлечённого — не больше 10 %; занятый — не больше 25 % душ забегов обычного; плательщик в ритуалах — не больше ×1,2; уникальных с ритуалов — не больше половины уникальных с боссов; рабочий дешевле половины героя;
  - перековка рабочих (`RULES.forge`, слова автора 29.09.2026): прогон тех же дней с перековкой избытка (`SIM.forge`: десять лучших — под бригады, остальные по три одной редкости — выше) против прогона без неё; артель к концу любого цикла — не больше 20, золото на перековку — не больше 3 % дохода забегов дня, базовых — не меньше, чем без перековки; плательщик — в пределах ×1,2. Таблицы `forgeRule`, `forge` и вариант «2 → 1» — `forgeAlt`. Окно перековки — `design/ui/screens/reforge.js`, проверка — `check_reforge.js`;
  - ступени загрузки (ADR-0047): мера — часы завершённых за неделю ритуалов по карточкам к часам своих мест за неделю, в целых процентах; платный ролл времени не добавляет. Правило — `RULES.ladder` (режим сундуков, часы недели), прогон — `SIM.ladder`: те же четыре профиля и пятый, «без простоя»; допуски — `TARGET.ladder`. Пороги и сундуки — слой ступеней режима `ritual` в `lootboxes.js`. Законы: обычный и увлечённый стоят на ступенях `typical` своего режима в каждом цикле; верхнюю берёт только профиль «без простоя»; плательщик — не выше обычного больше чем на ступень; ритуалы вместе с сундуками артели — не больше 15 % дохода забегов обычного. Загрузка в пределах `edge` пунктов от порога — предупреждение «на пороге», а не ошибка. В данные идёт `EN_RITUALS.ladder`: загрузка и ступень по циклам и профилям, доля дохода с сундуками. ## Энериум: ручеёк бесплатного игрока

`economy/enerium.js`, нужен Node. Черновик `docs/content/экономика-энериум.md` — слово автора 30.09.2026 (ADR-0033): «игрок по немногу сможет получать энериум и копить его… со временем он сможет на всё накопить». Своих данных игры не пишет, только таблицы черновика между метками; текст вокруг — ручной. Курс витрины — 1 рубль = 1 Энериум (ADR-0047) — ручеёк и цены за Энериум не меняет: покупки дают вдвое меньше Энериума за те же рубли.

- **Доход по источникам** в день и за цикл у обычного, увлечённого и плательщика при времени обычного: лист «Дар дня» и бесплатный ряд пропуска — `design/ui/pass.js`, контракты эпической редкости и выше — `design/ui/contracts.js` (`econ[цикл][профиль].en`), Арена топ-100 — `design/ui/arena.js` (`model.prof`); крафт обычного — модель стока `recipes.js`; реклама по желанию — `design/ui/store.js` (`ads`). Покупки плательщика — сегменты автора «от 100 ₽», «от 500 ₽», «от 2 500 ₽» (`SEGS` калькулятора) на витрине `design/ui/store.js`: выдача, платный ряд пропуска за деньги, наборы Энериума — первая покупка набора ×2, раз на набор, — и разовые наборы: ×2 одно, достаётся самому большому из взятых (ADR-0054).
- **Мерка «порядка трети»** (§9.3; решение координатора по ADR-0047) — `THIRD`: плательщик с пропуском и ежедневной выдачей, 748 ₽ в месяц. С ним сверяется доля бесплатного Энериума обычного; у сегмента «от 500 ₽» та же доля печатается для сведения.
- **Цели:** первый донатный герой, весь донатный сет, прокрутка и десять, кристалл и друза — сколько дней копить с начала цикла II: обычный, с рекламой, с призывами крафта, увлечённый, три сегмента и мерка. Платный ряд пропуска — не цель ручейка: он продаётся за деньги (слово автора 30.09.2026). Ещё — призывы крафта по циклам и прочие траты Энериума из данных режимов.
- **Где числа ручейка:** `pass/build.js` — `CAL` и `FREE`, `contracts/build.js` — `TARGET.en`, реклама — `store/build.js`, `ADS`.
- **Законы** (`LAWS`) — любой нарушен, и таблицы не пишутся: обычный игрой — от 25 до 50 в день в каждом цикле (слово автора); первый донатный герой — за 7 дней, прокрутка — раз в 4 дня, весь сет — за 70 дней, друза — за год; каждый сегмент быстрее обычного, крупнее — не медленнее; игрой — не больше ×1,7 обычного; бесплатный Энериум обычного — не больше половины Энериума плательщика-мерки; мерка стоит 748 ₽ в месяц, как записано в §9.3, — цена разошлась, и калькулятор падает.

## Лавка Энериума: витрина доната

Папка `store/`, нужен Node. Расчёт — `docs/content/монетизация.md`. Слово автора 30.09.2026 (ответ на ADR-0034): наборы малого, среднего, большого, огромного и великого Энериума; три подписки с Энериумом раз в день; боевой пропуск за деньги; лимитированные предложения; реклама за Энериум по желанию, с попапом; цены — для России и Запада. Слово автора 02.10.2026 (ADR-0047): курс — 1 рубль = 1 Энериум. Слово автора 06.10.2026 (ADR-0054): ×2 — два правила; прежние «пять стартовых наборов цепочкой, все ×2» отменены. Данные прототипа — `design/ui/store.js` (`window.EN_STORE` и алгоритм `window.EnStore`), руками не править.

- **×2 — два правила:**
  - разовые наборы, прежние «стартовые»: удвоение получает только самая первая покупка разового набора, набор выбирает игрок; один раз на игру. Порядок покупки — любой, каждый набор — раз за игру;
  - комплекты Энериума: у каждого своё ×2 первой покупки, один раз на комплект.
- `rules.js` — алгоритм «сервера» покупок, общий для калькулятора и прототипа: товар и его ступень цены в области игрока; множитель покупки `mult` — разовому набору `x`, пока удвоение ждёт (`onceX2`), комплекту `firstX`, пока он не куплен; что придёт (`gets`); можно ли купить (разовый набор — раз за игру, выдача — не больше `maxDays` вперёд, пропуск — раз за сезон, предложение — открыто и в лимите); реклама — дневной потолок. Память сервера о ×2: `x2.once` — какому разовому набору досталось удвоение; у комплекта — счёт покупок `bought`.
- `build.js` — данные витрины и законы: `RATE` — курс автора, `TIERS` — сетка цен (рубли и центы, коридор 75–100 ₽ за доллар ступени), `ONCE` — пять разовых наборов, `SEGMENTS` — пороги автора, `PACKS`, `SUBS`, `PASS`, `OFFERS`, `ADS`, `LAWS`, арт `ART`. В данных прототипа разовые наборы лежат под прежним ключом `chain`: его читают таблицы Excel и проверка обучения. Любая ошибка — файлы не пишутся:
  - курс: база каждого комплекта Энериума — ровно номинал его рублёвой цены (249 ₽ → 250, 2 490 ₽ → 2 500); малый набор — без прибавки, он базовый курс витрины; Энериум разового набора без удвоения — не выгоднее курса. Закон курса разовых наборов — в рублях; в долларах расхождение печатает таблица `onceLaws`;
  - рунные ключи и души — только в разовых наборах; все пять в худшем случае — удвоен самый большой — не больше 7 дней дохода обычного в цикле II по ключам и душам, плательщик с ними к концу цикла II — не больше ×1,7;
  - наборы растут по каждому ресурсу; наборы сегментов — около 100, 500 и 2 500 ₽; удвоение первой покупки — ×2;
  - комплекты: пять, имена автора по порядку, больше — не хуже курс в обеих валютах, первая покупка ×2; выдача — не хуже ×1,5 базового курса; Энериум платного ряда (`pass.js`, `rows.paid`) — от ×1 до ×2 базового курса цены ряда;
  - предложения — только Энериум, не выгоднее ×2 базового курса, живут не дольше недели; реклама — 10–15 Энериума в день, не больше 5 роликов.
- Читает: `design/ui/pass.js` (платный ряд), `design/ui/contracts.js` (ключи обычного), `contracts/capacity.json` (души обычного, длина цикла II), `design/ui/roster.js` (цены донатных героев и прокрутки — для сравнения); арт — `tools/art-gen/jobs/store.json`, `art/generated/manifest.json`, `design/ui/assets/art/store/`.
- `screens/check_store.js` — законы ×2 и номера операции: без номера — отказ, повтор номера ничего не выдаёт и не тратит удвоение; все 120 порядков покупки пяти разовых наборов проходят; какой бы набор ни был первым, удвоен только он; у каждого комплекта удвоена только первая покупка; лист «что придёт» называет ровно то, что выдаст сервер; общая пометка разовых наборов и печати комплектов стоят, только пока удвоение ждёт. Каждый закон проверен мутацией — поломкой «сервера», алгоритма или показа; законы сборщика о курсе и ×2 — мутацией данных. `--mut` печатает, что закон нашёл у каждой поломки.

## Клан

Папка `clan/`, нужны Python и Node. Черновик `docs/content/клан.md` (§24, §25), данные прототипа — `design/ui/clan.js` (`window.EN_CLAN` и алгоритмы `window.EnClan`), руками не править.

- `capacity.py` — сила главного отряда по дням циклов II–VI у обычного и увлечённого (`economy/echo.py`, `sets.py`) и норма силы цикла — средняя у обычного за цикл (`norm`, ADR-0042); пишет `capacity.json` рядом.
- `core.js` — алгоритмы, общие для калькулятора и прототипа: круг и уровень врагов, элиты круга (`roll`: стихии без повторов), цель и её свита (`card`, `retinue`: Голос или Хозяин сонма и четверо его сонма), бой одной атаки (`battle`, раунды — таблица ядра: элита 15, босс 35), своя копия цели в цикле атакующего и доля её здоровья (`circlePow(D, k, c)`, `hpIn`, `shareOff`), пересчёт очков между циклами по нормам (`toCycle`, `counted`, ADR-0042), очки, награды, раздача; ступени недели (ADR-0047): личные по личным очкам (`myNeed`, `myStep`), клановые по взятым кругам (`circlesDone`, `clanStep`, `circleRows`), пул клана — сундуки взятых клановых ступеней и места в топе (`pool`; строки «все с очками» нет). Мощь целей — та же формула §6 и та же C, что у общей функции мощи прототипа; проверка `check_heroes.js` сверяет обе.
- `foes.js` — сонмы стихий, враги кланового босса: семь стихий по восемь фигур, имена, облик и совет старика, записи сказителя, Хозяин недели по неделям рас. Контент, не числа: классы, наборы и образцы характеристик — `BOSS.host` в `build.js`.
- `build.js` — резервуар, древо, клановый босс, сонмы, награды, ×1,7, клан и разные циклы (ADR-0042): нормы циклов — первые личные планки контрактов, Событий и Эхо (`contracts.js`, `event.js`, `echo-rules.js`), прогон смешанных кланов и его законы. Приток резервуара — половина очков контрактов (`contracts.js`, `econ`), засчитанная по первой планке цикла. Отряд боёв — фикстура расчётов `biomes/sim.js` (`SQUAD`, ADR-0031, п. 1), своей копии нет. Пишет `clan.js` и таблицы документа между метками. Кроме входов выше читает:
  - `foes.js` — сонмы стихий;
  - `tools/art-gen/jobs/clan-foes.json` — задание арта сонмов: на каждую фигуру есть задание, промты — без спойлеров;
  - `tools/art-gen/ui-art.json` и `design/ui/assets/art/clan/` — какие портреты выгружены (`EN_CLAN.boss.art.ready`); отобранные файлы `art/generated/clan/` — таблица `ART_PICK`;
  - `tools/content-gen/lore/spoilers.js` — спойлеры дайджеста: тексты игрока о сонмах сборщик проверяет по ним.
- Ступени недели (ADR-0047) — `LAD` и `ladCalc` в `build.js`. Множители личных ступеней, круги клановых и сундуки — режим `clan` в `lootboxes.js`. Первую личную ступень подбирает `pickPlank1` по прогону: кратная `LAD.round`, при которой недели обычного лежат в его ступени с наибольшим запасом в обе стороны; она одна на все циклы. В данные идут `EN_CLAN.boss.ladder` — `{ mode, plank1, circles }` — и прогон `EN_CLAN.calc.ladder`. Законы: обычный — на ступени `typical.free`, выше — не чаще `LAD.strongBp`; увлечённый — на `typical.fan`, в пределах `LAD.edgeBp` от порога и на эталонных неделях — предупреждение; плательщик — не выше обычного больше чем на ступень; каждый клан прогона — на своей клановой ступени: без древа — первая, древо растёт — вторая, полное древо с выбором под босса — верхняя. Таблицы `ladMe`, `ladWho`, `ladRef`, `ladClan`, `ladClans`.

```bash
python tools/content-gen/clan/capacity.py        # после правки калькуляторов экономики
node tools/content-gen/clan/build.js             # собрать, около двух минут; --check — только проверить, --print — таблицы
node tools/content-gen/screens/check_clan.js     # --mut — что поймала каждая мутация ступеней
```

`check_clan.js`, раздел 4а — законы ступеней S1–S4 и их мутации: личные — по личным очкам и один раз, клановые — по взятым кругам, пул недели — ступени и место, законы калькулятора.

Пересобирать после контрактов, Событий, Эхо, сундуков, ядра боя и библиотеки. **После выгрузки арта сонмов** (`export_ui.py`) — тоже: список выгруженного в `clan.js` берётся из `ui-art.json` и папки выгрузки, без пересборки `--check` скажет «устарели». ## Новый цикл — новая ступень аккаунта

Папка `cycle/`, нужны Node и Python. Слово автора 01.10.2026: «новый цикл это новая ступень аккаунта игрока, больше планки для игроков»; уточнение — первый рейтинг — цикл II. Решение — ADR-0041, перечень по системам и расчёт — `docs/content/переход-цикла.md`.

- `data.js` — только то, чего нет в данных игры:
  - слово автора;
  - правила перехода — первый рейтинг, переход по рунному стражу второго биома, что выдаёт операция, рейтинги с нуля;
  - блоки окна `SECTIONS` — общие с окном I → II;
  - слова Хранителя знаний и подписи окна.
- `rules.js` — «сервер» перехода: одна операция с номером, повтор — прежний ответ, другой номер на тот же переход и устаревшее окно — отказ. Один файл на сборщик и прототип.
- `build.js` — пункты окна каждого перехода II → III … V → VI из данных игры: рецепты, состав, Эхо, Странник, контракты, Событие, Арена, ритуалы, лутбоксы, снаряжение, Лавка, Летопись, старт, пропуск, кривая ядра, `climb.json`.
  - Законы: у каждого перехода есть пункт в каждом блоке, рейтинг цикла и место Памяти; кривая ядра = калькуляторы = снаряжение; враги Эхо цикла N + 1 сильнее; тексты игрока без служебного; цикл VI — без имён бога и биомов; коридоры подъёма держатся.
  - Выход — `design/ui/cycle.js` (`EN_CYCLE` и алгоритм `rules.js`) и таблицы `docs/content/переход-цикла.md` между метками.
- `climb.py` и `climb-sim.js` — калькулятор подъёма по циклам II–VI, сроки автора (ADR-0043: II — 2 недели, III — 3 месяца, IV — год, V — 2 года, VI — 2+).
  - Доход по дням — правила калькулятора экономики; цикл II совпадает с ним день в день. Забегов разом — по уровню артефакта активных биомов: уровень своего цикла берётся, как только хватает душ (ADR-0054); в записи дня — слотов сегодня и душ, отданных за уровень.
  - Стоки — в данных: цена уровня × цикл героя (`RULES.levelCycle` в ядре), доблесть по одному герою (руна — одному, запасной держит место), рунные пределы — на пределе уровня, запас рун под круги доблести.
  - Ступени — пятёрки героев: за золото, Эхо, донатный сет.
    - Пятёрка Эхо (ADR-0047): комплект героя — по его циклу (`roster.js`, `rules.echoSet`); гарантия недельных сундуков (`lootboxes.js`, `week.echo`, `sure`) — герою-цели, старшему несобранному из открытых героев расы недели; связки сверх гарантии — поровну открытым; лишнее — в прах Эха, его вливают в героя старшего цикла, пока пятёрка не собрана; накопленный прах — в героев нового цикла в его первый день.
    - Донатный сет: у плательщика — с первого дня цикла; у обычного и увлечённого — за накопленный бесплатный Энериум (`economy/enerium.js --json`: ручеёк игрой по профилям и циклам, цены донатных героев). Высокая ступень цикла — та, что готова раньше: пятёрка Эхо или сет.
  - Бои — ядром на образцах биомов циклов III–VI по кривой §3.3 × сила цикла (`KX` — и цель силы биомов 5–12).
  - Законы: срок автора в коридоре; отряд прихода упирается в первый биом; отряд конца цикла берёт первый биом за забег; главная ступень не стоит дольше 14 дней; увлечённый быстрее; плательщик не медленнее и быстрее не больше ×1,7 — в цикле и на всей длине.
  - Выход — `climb.json` (его читает `build.js`) и `climb-days.json` — записи дня по профилям: их берут `economy/sets.py` (дни циклов III–VI для `echo.py`, ёмкости контрактов и клана) и `biomes/farm.py`.

```bash
python tools/content-gen/cycle/climb.py          # подъём по циклам — climb.json; --check — вердикт и свежесть
node tools/content-gen/cycle/build.js            # окно цикла — design/ui/cycle.js и таблицы; --check — законы и свежесть
```

## Таблицы Excel и спойлеры по циклам

Папка `tables/`, нужны Python 3 и Node. Слово автора 01.10.2026: имена таблиц автора и документов были заглушками — их делают по лору и базе ресурсов и рецептов; таблицы в `source-data/` должны показывать игру как она есть, «чтобы не было путаницы в будущем».

- **Книги** — `source-data/*.xlsx`, 18 штук. ## Порядок сборки

Каждая следующая ступень читает выход предыдущих. Шаг, чьи входы не менялись, можно пропустить: у сборщиков с `--check` это видно сразу.

**Правка правил боя в ядре** — таблицы раундов `RULES.rounds.by`, иммунитета `RULES.resist`, неприязни `RULES.aversion`, осады `RULES.siege`, доблести `RULES.valorPct`, здоровья врагов, черты врагов — начинается с перемеров: `economy/economy.py --sim` и `economy/echo.py --sim`, вывод — в их данные (`SIM*`), `economy/sets.py --sim` — `CLEAN_FROM`. Дальше — по порядку ниже, с шага 3; `arena/model.js` — обязательно. Правка чисел боевой мощи `RULES.bm` боя не меняет: пересобрать то, что печатает мощь, — `biomes/build.js`, `clan/build.js`, `foes/ladder.js`.

1. **Состав и способности:** `heroes/build_heroes.py`, `heroes/export_ui.py`, `heroes/export_roster.py`; `abilities/library.py`, `abilities/assign.py`, снова `heroes/export_ui.py`. Отряды недели Эхо (`echo/weeks/*.js`) пишутся в том же виде, что наборы героев: после их правки — `echo/build.js`, затем снова `assign.py`.
2. **Рецепты:** `recipes/build.js`, `recipes/tempo.py`, `recipes/assemble.js`. Модель стока читает ёмкость и ритуалы, темп — калькулятор экономики, сундуки, пропуск и достижения: после шагов 6–11 — снова эти три.
3. **Биомы, старт, подъём и Эхо:** `biomes/build.js`, `start/build.js`, `biomes/pace.py`, `cycle/climb.py`, `biomes/farm.py`, снова `biomes/build.js`; затем `economy/echo.py --js`, `echo/build.js`.
