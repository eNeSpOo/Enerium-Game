# Генераторы черновиков контента

Скрипты, из которых собраны черновики в `docs/content/` и данные окна «Древо рецептов». Черновики правятся здесь, в исходниках, а не в собранных файлах: иначе следующая сборка затрёт правку.

## Рецепты, ресурсы, дроп

Папка `recipes/`, нужны Node и Python. Редакция 30.09.2026 — поручение автора о крафте; решения — «Решено исполнителем» в документе.

- `common.js` — ремёсла, ярусы (`TIERS`) и семейства (`FAMS`), параметры добычи, лестница Энериума (`ENER`), руническая пыль (`DUST`), крафтовые места и призывы (`CRAFT`), модель стока (`SINK`). Числа — демонстрация, шансы в базисных пунктах.
- `basics.js` — общий пул из 36 базовых: падают во всех биомах с первого (ADR-0023).
- `global.js` — общее для всех циклов: Энериум и рунный ключ в ячейке, кристалл и друза, руническая пыль, строки рун.
- `c1.js` … `c6.js` — по циклу на файл:
  - биомы: шесть ключей, уникальный, эхо босса биома — перекрафт, призыв, трофей;
  - крафтовые места — руины и город: активация, ресурсы, две находки, босс, пробуждение, трофеи;
  - заготовки, изделия, карсты, топливо, приманки призывов — рецепт записан в самом предмете; развилки — в `recipes`;
  - герои из скрытых рецептов и награды мастерской.

  У каждого предмета — `hint` (подсказка Этриона) и `art` (строка арта иконки).
- `build.js` — сборка предметов и рецептов. Героев из крафта берёт из `docs/content/герои/состав-героев.csv`, только читает.
- `emit.js` — проверки и вывод `design/ui/recipes.js`:
  - достижимость до неподвижной точки;
  - правило §9.2 — не больше двух ресурсов одного ремесла; шесть ячеек и до 100 в ячейке;
  - цикл рецепта не раньше цикла выхода, у рецепта есть вход своего цикла;
  - места цепочкой: первый рецепт активации не просит добычи своего места и мест после него;
  - призывы: Энериум, уникальный, своя находка; пробуждения — призыв, Многоликий, находка;
  - ключи — в установившемся расходе, не меньше двух путей; мёртвых ресурсов нет;
  - лестница Энериума 100 : 1; только целые числа.
- `sheets.js` — листы иконок по 24 и 16, поле `sheet`.
- `sink.js` — модель стока: доход обычного за день (`contracts/capacity.json`, `design/ui/rituals.js`) против расхода мастерской; веса видов ресурса мест (`resWBp`); рунные ключи от крафта.
- `tables.js` — таблицы документов в `tables.md`.
- `tempo.py` — темп руны доблести у обычного с крафтом (`economy/economy.py`, `valor_pace`), таблицы в `tempo.md`; `--check` — ошибка, если крафт ускоряет руну доблести.
- `check_recipes.js` — проверка данных поручения по `recipes.js`: мёртвые, ключи, подсказки, арт, листы, лестница, Энериум и уникальный в призывах, тексты игрока.
- `doc-1.md` … `doc-5.md` — текст `docs/content/ресурсы-рецепты-дроп.md`, в `doc-4.md` — летопись Этриона; `doc-items.md` — `docs/content/ресурсы-каталог.md`; `doc-recipes.md` — `docs/content/рецепты-каталог.md`. Таблицы вставляются вместо `@@имя@@`, числа — вместо `{{имя}}`.
- `assemble.js` — склейка трёх документов.

Сборка:

```bash
node tools/content-gen/recipes/build.js
python tools/content-gen/recipes/tempo.py --check
node tools/content-gen/recipes/assemble.js
node tools/content-gen/recipes/check_recipes.js
```

## Лутбоксы

Папка `lootboxes/`, нужен Node. Черновик `docs/content/лутбоксы.md` — сундуки всех режимов (§23, ADR-0023, п. 7).

- `build.js` — данные сундуков в начале файла: окна редкостей, линии пула, сундуки, выплаты режимов, допущения. Дальше — сборка, проверки и вывод:
  - `design/ui/lootboxes.js` — данные и алгоритм открытия для UI-кита, руками не править;
  - `tables.md` — таблицы для документа;
  - `docs/content/лутбоксы.md` — текст `doc.md`, таблицы вместо `@@имя@@`, числа вместо `{{имя}}`.
- `open.js` — открытие сундука: три броска генератора на предмет, генератор — как в ядре боя. Сборщик вставляет его в `lootboxes.js` как есть.
- `xlsx.js` — чтение листа xlsx без библиотек: талисманы и их веса из `source-data/`.
- Только читает: `design/ui/recipes.js`, `docs/content/герои/состав-героев.csv`, `source-data/Enerium_Талисманы_Финал.xlsx`, `design/ui/talismans.js` — имена, описания, виды и пометка «для команды» талисманов после переработки, `docs/lore/дайджест.md` — раздел «Нельзя показывать раннему игроку», `design/ui/battle.js` — для сверки генератора.
- `check_ui.js` — автопроверка раздела «Лутбоксы» в UI-ките без браузера: CRLF и синтаксис `index.html`, выполнение скриптов прототипа в песочнице, отрисовка раздела на всех сундуках, редкостях, окнах, циклах и неделях; без флажка «для команды» — ни одного спойлерного имени.
- Проверки — любая ошибка, и файлы не пишутся:
  - окна дают 10 000 б. п., ни в одной выплате нет редкости без записей;
  - каждый предмет пула есть в источнике и падает, а не создаётся рецептом; душ, Энериума и рун нет;
  - каждый герой Эхо и каждая редкость талисманов, рабочих и снаряжения выпадают хоть из одного сундука;
  - ×1,7 по планкам, разброс и удержание Эхо (§17.6);
  - лучшее место даёт не меньше худшего;
  - открытие на сиде сходится с точным расчётом, генератор совпадает с `battle.js`;
  - номер, редкость и вес талисмана — как в таблице автора и в `talismans.js`;
  - спойлеры в именах и описаниях талисманов — по словам раздела дайджеста. Спойлеры таблицы автора и решение по ним — таблица документа; итоговое имя или описание со спойлером без пометки «для команды» в `talismans.js` — ошибка. Такие талисманы есть в сундуках только с цикла VI.

Календарь — лист «Дар дня» из `pass/build.js` (`CAL`, ADR-0030, п. 22в; ADR-0031, п. 20): строки сундуков календаря сборщик собирает из листа, своего календаря у него нет. `pass/build.js --check` сверяет лист с календарём `lootboxes.js`: разошлись — пересобрать лутбоксы.

Сначала — талисманы: лутбоксы берут из них имена.

```bash
node tools/content-gen/talismans/build.js
cd tools/content-gen/lootboxes && node build.js && node check_ui.js
```

Перезапускать после правки `recipes.js` или состава героев: пулы и отряды Эхо берутся оттуда.

Где неделю заканчивают игроки в «Контрактах» — не допущение, а прогон сборщика контрактов: сборка читает `design/ui/contracts.js` и сверяет планку обычного и увлечённого во всех циклах. Разошлось — ошибка сборки: поправить `typical` режима «Контракты». Сборщик контрактов читает `lootboxes.js`, но не `typical` — круга нет.

## Герои

Исходник — markdown `docs/content/герои/цикл-N.md`. Оба скрипта читают его и ничего в нём не меняют. Нужен Python 3.
- `heroes/build_heroes.py` собирает `docs/content/герои/герои.csv`, проверяет сеты — 5 героев и бюджет доблести 15 — и печатает распределения по классам, стихиям и расам.
- `heroes/export_ui.py` выгружает героев и сеты в `design/ui/heroes.js` для раздела «Герои» в UI-ките. В выгрузке: витрина, роль, обрывки, главы, бонусы сетов, мотивы дедукции и заметки команды.

```bash
python tools/content-gen/heroes/build_heroes.py
python tools/content-gen/heroes/export_ui.py
```

После правки циклов запускайте оба скрипта.

### Состав героев

`heroes/export_roster.py` выгружает состав игры в `design/ui/roster.js` — для «Героев → Коллекции», «Призыва» и раздела «Состав героев» в UI-ките. Файлы только читает:
- `docs/content/герои/состав-героев.csv` — столбцы по имени, лишние не мешают. «Неприязнь» героя Эхо берётся из одноимённого столбца, иначе — раса его недели;
- тексты глав `docs/content/герои/главы/цикл-N.md`: `## <id> · <имя>`, затем `### <номер> · <заголовок>` и текст. Нет файла — только заголовки глав из CSV;
- ордены черновиков `docs/content/герои/герои.csv`: герой черновика сохраняет орден, донатный — только свой сет;
- механики и N по ступеням — `docs/content/сет-бонусы.md`;
- бонусы донатных сетов и древние цивилизации недель Эхо — `состав-героев.md`.

Числа — в блоке «ДАННЫЕ» в начале скрипта. `RULES['stub']` — заглушки прототипа, чисел нет в источниках. Правила источника — тоже данные (ADR-0019; ADR-0030, п. 5а): `RULES['maxV']` — личный максимум доблести по источнику и циклу героя, у рулетки II — 2, III–IV — 3, V–VI — 4; `RULES['rarity']` — редкости источника, за золото только обычная и редкая. Скрипт проверяет источники, редкости и максимумы по этим правилам — расхождение с ними ошибка, — каталог золота по редкости после мест обучения, места донатных сетов и заголовки глав. Остальные расхождения печатает предупреждениями, неразобранные строки — ошибками. В `srcInfo` источника — `maxByC`, максимум по циклу героя, и `rar`, героев по редкостям.

Пол героя (`sex`: `m` или `f`) — для портрета Странника: игрок выбирает портрет из своих героев своего пола. Берётся из столбца «пол» состава («м» или «ж»), если он есть; иначе сборщик выводит его из грамматического рода — первое сказуемое каждого предложения «кто он», слово-название в начале («Эльфийка», «Стражница»), «Её» или «Его», и сильнее всего — голос героя в главах: глагол рядом с «я» («я пришла», «давала я»). Правила и списки слов — `SEX` в блоке «ДАННЫЕ». Не вывелся — предупреждение, поле не пишется. Сейчас выведен у всех 360: 204 мужчины, 156 женщин.

```bash
python tools/content-gen/heroes/export_roster.py
```

После правки состава, глав или сет-бонусов запускайте его заново.

## Способности

Папка `abilities/`, нужен Python 3.
- `extract.py` выгружает таблицу автора `source-data/Enerium_Способности_элементов.xlsx` в `source.json`. Оригинал не меняется.
- `library.py` собирает библиотеку способностей по ADR-0015: восемь наборов — семь школ и «Без школы» — по восемь видов в трёх ступенях по числу целей, ульты, пассивки и реакции, общий набор фарма. Пишет `library.json` для ядра, черновик `docs/content/библиотека-способностей.md` и `design/ui/abilities.js` — раздел «Библиотека способностей» в UI-ките. Проверяет, что названия не повторяются, каждое из 72 названий таблицы использовано один раз, а контроль, дебафф и бафф у наборов свои.

- `assign.py` собирает наборы способностей всем героям состава `docs/content/герои/состав-героев.csv` и врагам Мастерской (ADR-0016, ADR-0031, п. 7). Класс, школа, редкость и личный максимум доблести — из состава. Набор сжат к личному максимуму: доблесть 0 — первая активная, дальше по порядку набора, последняя доблесть — ульта. Источники набора: 110 ручных наборов героев черновиков `герои.csv` (герой состава находит свой по столбцу «из черновика»; не подошёл по классу или школе — не берётся), наборы отрядов недели Эхо из `design/ui/echo-foes.js`, остальным — автомат по правилам ADR-0016, с сидом от id героя и без повторов активных в сете. Пишет `kits.json` (`roster` — наборы героев состава, `heroes` — ручные наборы черновиков как собраны), черновик `docs/content/распределение-способностей.md` и `design/ui/kits.js` — наборы для ядра боя прототипа по id героя состава; id черновика ведёт к тому же набору. Проверяет инварианты: набор у каждого героя, шагов — максимум + 1, ульта ровно на последней доблести, школа героя, у донатных героев поддержки — без урона. `--check` — только сверка, что выходы свежие. После правки состава или отрядов Эхо (`echo/build.js`) — перезапустить, затем перемеры `economy.py --sim`, `sets.py --sim`, `echo.py --sim`: отряд прототипа меряется этими наборами. Наборы попадают в карточку героя UI-кита черновиков через `heroes/export_ui.py` — запускайте его после `assign.py`.
- `check_core.js` — автопроверка библиотеки и наборов в ядре боя прототипа, нужен Node. Каждая из 339 способностей срабатывает в подобранном бою без ошибок, числа боя и добычи остаются целыми. У каждого героя состава — набор по id: шагов — максимум доблести + 1, пустых доблестей нет, ульта ровно на последней, способности своей школы; ядро находит набор через `EB.heroSrc`, дымовой бой по источникам проходит. Запускайте после `library.py` и `assign.py` и после правок `design/ui/battle.js`.

```bash
python tools/content-gen/abilities/extract.py
python tools/content-gen/abilities/library.py
python tools/content-gen/abilities/assign.py
python tools/content-gen/heroes/export_ui.py
node tools/content-gen/abilities/check_core.js
```

## Экономика

`economy/economy.py` — калькулятор к `docs/content/экономика-золото-дух.md`: цена уровней и кругов героя, доход забега, сроки. Числа — данными в начале файла, только целые. Т7 «Другие каналы» берёт доход контрактов из их прогона — `design/ui/contracts.js`, `econ`: после пересборки контрактов перезапустить и вставить Т7 в черновик. Калькуляторы, что импортируют `economy.py`, этот файл не читают. Флаг `--sim` перемеряет бой через Node: `design/ui/battle.js` с наборами способностей из `abilities.js` и `kits.js`; вывод вставить в `SIM`. Темп цикла I по ADR-0018 — таблица Т15. Коллекция Т3 — личные максимумы по составу `состав-героев.csv` (`HEROES_VALOR`, при запуске сверяется). Нужен Python 3.

Финальный прогон (ADR-0031):
- **отряд прогонов — одна фикстура** `biomes/sim.js`, `SQUAD`: пятеро золотых героев цикла I с максимумом доблести 1, доблесть 0, у бойца урона 1 от руны обучения. Её берут `economy.py --sim`, `sets.py --sim`, `echo.py --sim` и прогон темпа; демо `index.html` — те же герои;
- **числа стражей, слоты и рецепты рун — из `design/ui/recipes.js`** (`economy.rx()`): вход к стражам, шанс рунного ключа с босса, осколки стража доблести, общий кап, забегов одновременно по циклам (`drops.activeSlots` — номер цикла). Своих копий у калькуляторов нет — ручки в `recipes/common.js`;
- **стражи — из ключей по дням** (`economy.timeline_ex`): ключи контрактов профиля из `contracts.js` (`econ[цикл].o / e / p`) и ключ с босса за вчерашние забеги, побед — сколько хватит ключей при доле 7 : 3, не выше капа. Руны пределов и осколки доблести — по дням; пятый предел — руны V и 1200-й уровень, с него доступна доблесть;
- **длина цикла II — одна:** `economy.CYCLE_DAYS` читает `biomes/pace.json`, `cycleDays` — день, когда обычный берёт стража последнего биома цикла II. Остальные калькуляторы берут её из `economy.py` или из `contracts/capacity.json` (`cycleDays`).

```bash
python tools/content-gen/economy/economy.py
```

```bash
python tools/content-gen/economy/economy.py --sim
```

`economy/sets.py` — калькулятор сет-бонусов к `docs/content/сет-бонусы.md`: ступени сетов, доли дохода, ключи против капа рунных стражей, правило ×1,7, герои за золото. Ключи контрактов берёт из прогона контрактов — `econ[цикл][профиль].ctKeys` в `design/ui/contracts.js`: награды заданий, сундук недельного контракта и сундуки планок, без ключей с боссов. Таблицы С1–С10а документа — его вывод без правок. Перезапускать после пересборки контрактов.

```bash
python tools/content-gen/economy/sets.py
```

`economy/echo.py` — калькулятор боя в Эхо к `docs/content/эхо-экономика.md` (ADR-0025). Считает:
- уровень и здоровье врагов по ступеням и циклам; раунды по типу врага — выборка таблицы ядра `RULES.rounds.by` (через Node), своих чисел раундов нет;
- крафтовый («забытый») босс — тип `craft`: 75 раундов, здоровье по прогону, цена атаки — раунды × цена раунда (`roundSouls`); срок боссов, Убера и крафтового — час;
- души за атаку, вершину лестницы за неделю, рейтинговые очки, планки;
- Многоликого и его биом.

Доход душ и уровни отряда он берёт из `economy.py` и `sets.py` через importlib и их не меняет. Числа — данными в начале файла, только целые.
- `--sim` меряет бой ядром через Node на врагах недели из `design/ui/echo-foes.js`; вывод вставить в `SIM_*`.
- `--js` собирает `design/ui/echo-rules.js` — `window.EN_ECHO_RULES`, руками не править, формат — в шапке файла.
- `--doc` заменяет таблицы Э1–Э18 в черновике выводом скрипта; повторная сборка даёт те же байты.
- `--check` — цели ADR-0031, п. 8: обычный в 1-ю и среднюю неделю цикла II берёт босса недели за дневной бюджет душ Эхо, крафтового — за один-два дня; Убер — у увлечённого с цикла II; первая планка — в 1-ю неделю обычного; ×1,7 плательщика по очкам Эхо; свежесть `echo-rules.js`.

- `pool.js` — алгоритм, общий для калькулятора и прототипа: слоты, роллы и карточки по уровням артефактов, пул вкладки на сиде (у рабочих пять бросков на карточку — уникальный, редкость, бригада, биом, имя; у героев три), награда карточки, время с ускорением рабочих, исход старта на сиде карточки, цена пробуждения рабочего. Сборщик вставляет его в `rituals.js` как есть.
- `build.js` — раздел «ДАННЫЕ»: правила §19 и таблиц автора, сетка по вкладкам, бригады, ставки наград, имена, тексты игрока; допущения прогона и цели долей. Дальше — прогон дней циклов II–VI у обычного, увлечённого, занятого и плательщика тем же пулом на сидах, приток шардов из сундуков `lootboxes.js`, сравнение с доходом забегов из `contracts/capacity.json`. Пишет `design/ui/rituals.js` и таблицы документа между метками `<!-- @таблица имя -->` и `<!-- /таблица имя -->`; текст документа — ручной.
- Проверки — любая ошибка, и файлы не пишутся:
  - генератор совпадает с сундуками (`EnLoot`); всё целое, длительности кратны 10 000 мс; сетка 30 минут — 12 часов, рабочие вдвое короче; бригада 1–5; души — только у героев;
  - шаг и потолок «Караванного шатра» сходятся с `wanderer.js`; у каждого биома шесть ключей и уникальный; общий пул — 36;
  - пул детерминирован, уникальный — только в бесплатном и не больше одного, биом — открытый; исход даёт столько предметов, сколько на карточке;
  - доли ритуалов у обычного — в целях по золоту, духу, душам и базовым; у увлечённого — не больше 10 %; занятый — не больше 25 % душ забегов обычного; плательщик в ритуалах — не больше ×1,2; уникальных с ритуалов — не больше половины уникальных с боссов; рабочий дешевле половины героя;
  - перековка рабочих (`RULES.forge`, слова автора 29.09.2026): прогон тех же дней с перековкой избытка (`SIM.forge`: десять лучших — под бригады, остальные по три одной редкости — выше) против прогона без неё; артель к концу любого цикла — не больше 20, золото на перековку — не больше 3 % дохода забегов дня, базовых — не меньше, чем без перековки; плательщик — в пределах ×1,2. Таблицы `forgeRule`, `forge` и вариант «2 → 1» — `forgeAlt`. Окно перековки — `design/ui/screens/reforge.js`, проверка — `check_reforge.js`.

```bash
node tools/content-gen/rituals/build.js                 # собрать; --check — только проверить, --print — таблицы и при ошибках
node tools/content-gen/screens/check_rituals.js
```

Пересобирать после правки `capacity.json`, сундуков в `lootboxes.js`, артефактов в `wanderer.js` или биомов в `recipes.js`.

## Арена и Лига

Папка `arena/`, нужен Node. Черновик `docs/content/арена-и-лига.md` (§20), данные прототипа — `design/ui/arena.js` (`window.EN_ARENA` и алгоритм `window.EnArena`), руками не править.

- `rules.js` — правила в данных:
  - Эло: старт, K, асимметрия защиты, сезонный сброс;
  - подбор, попытки, список — новый после каждого боя (`refresh.auto`) и «Обновить» руками: бесплатные за сутки и цены платных; пороги первых планок, дивизионы Лиги, Энериум топ-100;
  - предел раундов — из таблицы ядра `RULES.rounds.by.pvp`: `rules.js` загружает `battle.js` и своего числа не держит.

  Таблица ожидания Эло — целочисленным корнем 400-й степени, без дробей.
- `elo.js` — алгоритм, общий для калькулятора и прототипа: ожидание и сдвиг рейтинга, атака с асимметрией, сброс, бой PvP ядром, его исход и статистика для итога (`pvpRun` — шаги ядра и его события: кто сколько нанёс, вылечил и принял, что сработало), матч Лиги, подбор и новый список после боя (`pickFresh`), цена «Обновить» (`refreshCost`), Энериум за место. Сборщик вставляет его в `arena.js` как есть.
- `model.js` — прогон, пишет `model.json`:
  - бой PvP ядром на героях состава: предел раундов, сила за уровень, выгода выбора отряда, сторона;
  - рейтинг на 5 000 модельных игроках, три профиля, четыре сезона, список новый после каждой атаки: выгода равной атаки при прочтениях сдвига защиты, дрейф, совпадение рейтинга и силы, победы за неделю, ручные обновления, Энериум топа, ×1,7 плательщика против увлечённого; для сравнения — тот же сервер с прежним правилом списка;
  - Лига: цена расстановки трёх отрядов.

  Около 20 секунд. Меняет победы за неделю — после него пересобрать и достижения: `wanderer/build.js` берёт их из `arena.js`.
- `build.js` — правила, прогон и демо-сервер: соперники Арены и Лиги из героев состава с наборами. Пишет `design/ui/arena.js` и таблицы документа между метками `<!-- @таблица имя -->` и `<!-- /таблица имя -->`; текст документа — ручной.
- Проверки сборщика — любая ошибка, и файлы не пишутся:
  - таблица Эло;
  - с каких циклов рейтинг — как у сундуков;
  - выгода равной атаки — около нуля;
  - пороги планок дают обычному и увлечённому те же планки, что typical лутбоксов;
  - плательщик при той же силе — не больше ×1,7 по победам и Энериуму, обновления не окупаются;
  - прогон несёт сравнение с прежним правилом списка; бесплатных обновлений увлечённому хватает — иначе предупреждение;
  - у соперников пятеро разных героев с наборами, в Лиге — 15 разных.

```bash
node tools/content-gen/arena/model.js                    # после правки ядра боя, наборов, состава героев или правил
node tools/content-gen/arena/build.js                    # собрать; --check — только проверить, --print — таблицы и при ошибках
node tools/content-gen/screens/check_arena.js
```

Читает `design/ui/lootboxes.js` (typical, планки), `roster.js`, `kits.js`, `echo-foes.js`, образцы классов `HR_DATA` из `design/ui/screens/heroes.js`. После пересборки сундуков или состава героев — пересобрать Арену. Правило Лиги — `rules.js`, `league`: цикл рейтинга и 15 разных героев. Его же берут экраны Лиги и контрактов, калькуляторы контрактов, Событий и достижений.

## Событие недели

Папка `event/`, нужен Node. Черновик `docs/content/событие.md` (§27), данные прототипа — `design/ui/event.js` (`window.EN_EVENT` и алгоритм `window.EnEvent`), руками не править.

- `rules.js` — алгоритм «сервера», общий для калькулятора и прототипа: очки за дело с акцентом недели и силой коллекции, планки, клановые планки, место. Сборщик вставляет его в `event.js` как есть.
- `build.js` — раздел «ДАННЫЕ»: цены единиц, дневные потолки, девять Событий с акцентом, допущения прогона, законы. Дальше — ёмкость дня (`dayUnits`), прогон недель, пороги планок, кланы, ×1,7, демо. Пишет `event.js` и таблицы документа между метками; текст документа — ручной.
- Читает `contracts/capacity.json`, `design/ui/contracts.js` (ёмкость и прогон контрактов), `echo-rules.js`, `lootboxes.js`, `roster.js`, `wanderer/pace-inputs.json` и правило Лиги `arena/rules.js`. День открытия Лиги — `leagueOpen`, матчи Лиги — только в эти дни.

Демо — один календарь прототипа, `DEMO.elapsedS` — время от начала недели по `S.week.left` в `index.html`.

```bash

```

## Клан

Папка `clan/`, нужны Python и Node. Черновик `docs/content/клан.md` (§24, §25), данные прототипа — `design/ui/clan.js` (`window.EN_CLAN` и алгоритмы `window.EnClan`), руками не править.

- `capacity.py` — сила главного отряда по дням циклов II–VI у обычного и увлечённого (`economy/echo.py`, `sets.py`); пишет `capacity.json` рядом.
- `core.js` — алгоритмы, общие для калькулятора и прототипа: круг и уровень врагов, элиты круга (`roll`: стихии без повторов), цель и её свита (`card`, `retinue`: Голос или Хозяин сонма и четверо его сонма), бой одной атаки (`battle`, раунды — таблица ядра: элита 10, босс 100), очки, награды, раздача. Мощь целей — та же формула §6 и та же C, что у общей функции мощи прототипа; проверка `check_heroes.js` сверяет обе.
- `foes.js` — сонмы стихий, враги кланового босса: семь стихий по восемь фигур, имена, облик и совет старика, записи сказителя, Хозяин недели по неделям рас. Контент, не числа: классы, наборы и образцы характеристик — `BOSS.host` в `build.js`.
- `build.js` — резервуар, древо, клановый босс, сонмы, награды, ×1,7. Приток резервуара — половина очков контрактов (`contracts.js`, `econ`). Отряд боёв — фикстура расчётов `biomes/sim.js` (`SQUAD`, ADR-0031, п. 1), своей копии нет. Пишет `clan.js` и таблицы документа между метками. Кроме входов выше читает:
  - `foes.js` — сонмы стихий;
  - `tools/art-gen/jobs/clan-foes.json` — задание арта сонмов: на каждую фигуру есть задание, промты — без спойлеров;
  - `tools/art-gen/ui-art.json` и `design/ui/assets/art/clan/` — какие портреты выгружены (`EN_CLAN.boss.art.ready`); отобранные файлы `art/generated/clan/` — таблица `ART_PICK`;
  - `tools/content-gen/lore/spoilers.js` — спойлеры дайджеста: тексты игрока о сонмах сборщик проверяет по ним.

```bash
python tools/content-gen/clan/capacity.py        # после правки калькуляторов экономики
node tools/content-gen/clan/build.js             # собрать; --check — только проверить, --print — таблицы
node tools/content-gen/screens/check_clan.js
```

Пересобирать после контрактов, сундуков, ядра боя и библиотеки. **После выгрузки арта сонмов** (`export_ui.py`) — тоже: список выгруженного в `clan.js` берётся из `ui-art.json` и папки выгрузки, без пересборки `--check` скажет «устарели». Около минуты: у каждой цели десять сидов (ADR-0031: у стены урон атаки мал, шести не хватало).

- `chapters.js` — разделы книги, главы лора, условия открытия, тексты и выбор картинок. Главы правятся только здесь.

## Порядок сборки

Каждая следующая ступень читает выход предыдущих. Шаг, чьи входы не менялись, можно пропустить: у сборщиков с `--check` это видно сразу.

**Правка правил боя в ядре** — таблицы раундов `RULES.rounds.by`, осады `RULES.siege`, доблести `RULES.valorPct`, здоровья врагов — начинается с перемеров: `economy/economy.py --sim` и `economy/echo.py --sim`, вывод — в их данные (`SIM*`), `economy/sets.py --sim` — `CLEAN_FROM`. Дальше — по порядку ниже, с шага 3; `arena/model.js` — обязательно.

1. **Состав и способности:** `heroes/build_heroes.py`, `heroes/export_ui.py`, `heroes/export_roster.py`; `abilities/library.py`, `abilities/assign.py`, снова `heroes/export_ui.py`.
2. **Рецепты:** `recipes/build.js`, `recipes/tempo.py`, `recipes/assemble.js`. Модель стока читает ёмкость и ритуалы, темп — калькулятор экономики: после шагов 6–8 — снова эти три.
3. **Биомы и Эхо:** `biomes/build.js`, `biomes/pace.py`, снова `biomes/build.js`; затем `economy/echo.py --js`, `echo/build.js`. Эхо берёт длину цикла II из прогона темпа (`pace.json`, `cycleDays`), поэтому темп — первым.
4. **Талисманы, затем лутбоксы:** `talismans/build.js`, `lootboxes/build.js` и `lootboxes/check_ui.js`. Лутбоксы берут имена у талисманов; талисманы считают экономику по сундукам.
5. **Снаряжение и Арена:** `equipment/build.js`; `arena/model.js`, если менялись ядро, наборы, состав или правила, затем `arena/build.js`.
6. **Ёмкость и контракты:** `contracts/capacity.py`, `contracts/build.js`. Контракты берут у События только правила. День открытия Лиги они берут у `leagueOpen`: по `pace-inputs.json` и правилу Арены.
7. **Калькуляторы экономики после контрактов:** `economy/sets.py` — таблицы С1–С10а сет-бонусов, в них ключи контрактов; `economy/economy.py` — Т7; `wanderer/pace_inputs.py`. Сдвинулся день Лиги в `leagueOpen` — вернуться к шагу 6.
8. **Ритуалы:** `rituals/build.js`.
9. **Событие:** `event/build.js` — после контрактов.
10. **Клан:** `clan/capacity.py`, `clan/build.js` — после контрактов.
11. **Достижения:** `wanderer/build.js` — после контрактов, Арены, ритуалов и События. Контракты читают из `wanderer.js` только артефакты, Память и список достижений с бесплатными заменами. Изменился этот список — снова шаг 6.
12. **Летопись:** `lore/build.js` — ни от кого не зависит; после выгрузки арта глав — снова.
13. **Проверки:** `abilities/check_core.js`, все `screens/check_*.js`, `recipes/check_recipes.js`, `recipes/tempo.py --check`, `lootboxes/check_ui.js`, `--check` у сборщиков контрактов, События, клана, ритуалов, Арены, снаряжения, талисманов, достижений, пропуска и Летописи, `biomes/pace.py --check`, `economy/echo.py --check`, `contracts/capacity.py --check`, `clan/capacity.py --check`, `wanderer/pace_inputs.py --check`.
