Порядок — по слову автора. Список — из двух мест:

## Как работать с автором

Эти правила пришли из его замечаний; в прежнем аккаунте они жили в памяти чата.

1. **Слова автора — буквально.** Его числа — как написаны; своё «лучше» — только предложением рядом. Его снимки экрана — тоже поручения. Перед отчётом — чек-лист по точному тексту его сообщений.
2. **Перед вопросом автору — сверка с GDD и ADR.** Вопросы подагентов фильтровать: спрашивать только то, что источники оставляют открытым. Мелкое — «реши сам», решение записать.
3. **Перед задачей по спорному месту — написать автору, как понял его,** и ждать «+».
4. **Поиск в интернете — сам, не подагентами:** каждый их заход на страницу просит у автора разрешение.
5. **Экраны — глазами.** После агента интерфейса — кадры `node tools/ui-shots/shots.js` на 932 × 430 и 844 × 390; кадрам панели браузера не верить, когда автор отошёл.
6. **Коммит во время работы агентов — только свои пути:** `git commit -m "…" -- <пути>`; сначала посмотреть индекс. Агенты ставят правки в индекс через `git mv`.
7. **Подагенту отказали в действии — самому его не выполнять,** спросить автора.
8. **Отчёт — коротко:** состояние, а не пересказ.
9. Папку `outputs/` (выгрузки другой нейросети) и архив `Enerium-archive` без слова автора не читать.
10. Перед коммитом — проверка, что ключ API не попал в файлы; push делает автор.
